# Python to TypeScript Migration Plan

## 원칙

기존 Python 코드를 줄 단위로 번역하지 않는다. Python 프로그램의 사용자 동작,
검증 규칙, 저장 데이터와 오류 처리를 조사한 뒤 TypeScript 구조에 맞게 다시
구현한다.

Python 기준 구현은 전체 마이그레이션과 검증이 끝날 때까지 삭제하거나 수정하지
않는다.

## 기능 이전 순서

1. Python 기능과 데이터 형식 전체 목록 작성
2. 프로젝트 생성·목록·저장·불러오기
3. 설정, API 상태와 예산 관리
4. 캐릭터와 Reference Asset 관리
5. Style, Lore, Memory 등 실제 사용 중인 창작 데이터
6. 대본과 정확히 6개 장면 생성
7. 이미지 생성, 검토와 장면별 재생성
8. Runway 프롬프트·비용 Preview와 승인 Gate
9. 영상 순차 생성, 중지, 재시도와 비정상 종료 복구
10. 장면별 영상 검토와 사용 확정
11. FFmpeg 검사·병합과 최종 MP4 검증
12. 전체 Python 동등성 검사
13. 로컬 배포와 이후 서버 확장 준비

## 기능별 완료 조건

기능 하나가 완료되려면 다음을 모두 만족해야 한다.

- 기존 Python 동작과 데이터 규칙이 문서화됨
- 필요한 공유 타입과 API 계약이 확정됨
- Frontend 사용자 흐름이 구현됨
- Backend 로직과 저장이 구현됨
- 오류와 경계 조건 테스트가 있음
- 실제 유료 Provider를 호출하지 않는 통합 테스트가 통과함
- Main 브랜치에서 typecheck, test와 build가 통과함

UI나 Backend 한쪽만 구현된 경우 완료로 표시하지 않는다.

## 다음 작업

코드를 수정하기 전에 Main이 `app/`, `tests/`, `prompts/`를 조사해 실제 기능
목록을 이 문서에 추가한다. 이후 첫 번째 기능만 선택해 Frontend와 Backend에
작업을 분배한다.
