# Current Product Specification

## 목표

사용자가 주제를 입력하면 대본과 설정한 장면 수(프로젝트별 2~12개)만큼의 장면·
이미지를 생성한다. 사용자가 이미지와 영상 생성 조건을 검토한 뒤 명시적으로
승인하면 Runway로 장면별 영상을 생성한다. 사용자가 확정한 영상을 장면 수만큼
FFmpeg로 순서대로 병합해 Instagram Reels용 최종 MP4를 만든다. 내레이션(음성)과
자막은 프로젝트 설정에서 선택적으로 켤 수 있다.

초기 사용자는 한 명이며 로컬 PC에서 실행한다. 이후 서버 배포와 회원가입을
추가할 수 있도록 프론트엔드와 백엔드를 분리하지만, 지금 계정 기능을 구현하지
않는다.

## 고정 흐름

```text
프로젝트 설정 및 필수 조건 검사
→ 대본과 설정한 장면 수(2~12)만큼 장면 생성
→ 장면 수만큼 이미지 생성
→ 사용자 이미지 검토 및 필요한 장면만 재생성
→ 장면별 Runway 프롬프트와 예상 비용 확인·수정
→ 사용자의 명시적 전송 승인
→ 첫 장면부터 마지막 장면까지 영상 순차 생성
→ 장면별 영상 검토 및 사용 확정
→ 확정된 영상을 장면 수만큼 FFmpeg 병합
→ Instagram Reels용 최종 MP4 생성
```

## 영상 기본값

- Runway 모델: 설정 화면에서 고른다. 기본값은 `gen4_turbo` 이고, **견적과 예산 검사가 고른 모델의 단가를**
  **따라간다** — 단가를 안 따라가는 선택기는 선택기가 없느니만 못하다(계약의 `VIDEO_MODEL_OPTIONS`).
- 장면 수: 프로젝트별 2~12개(Wizard/설정에서 지정, 기본값은 화면에서 안내)
- 장면 길이: 5초 또는 10초. 회차는 **총 길이 ÷ 장면 수**로 정해진다(계약의 `clipDurationSecondsPerScene`) —
  그 값이 곧 가격이다. Runway 는 초당 과금이다.
- 출력: `720:1280`, 9:16
- 실행: 첫 장면부터 순차 생성
- 연결 강도: `보통`
- 이전 장면 종료 움직임을 다음 장면 시작 프롬프트에 반영

## 내레이션과 자막 (선택 기능)

- 프로젝트 설정에서 내레이션(음성)과 자막을 각각 독립적으로 켤 수 있다. 기본값은 둘 다 꺼짐(무음)이다.
- 대본 생성 시 장면별 내레이션 문장을 함께 만든다. 이미 승인된 대본은 대본 화면에서 문장만 직접 수정할 수 있다.
- 내레이션을 켠 경우에만 장면별 음성을 유료 Provider로 생성하며, 켜지 않으면 비용이 들지 않는다.
- 자막은 내레이션 문장을 화면에 표시하는 선택 기능으로 별도 Provider 호출이 없다.
- 문장이 없는 장면은 유료 생성 버튼을 표시하지 않는다.

## 승인과 비용

- 프롬프트 확인, 수정 또는 창 닫기만으로 유료 요청을 보내지 않는다.
- 전송 직전에 모델, 해상도, 장면 수, 길이, 프롬프트, 최대 호출 수,
  예상 비용과 남은 로컬 예산을 표시한다.
- OpenAI 예산과 Runway 예산은 분리한다.
- Runway 로컬 월 예산 초기 기본값은 10 USD이다.
- 모든 유료 요청은 공통 Budget 실행 경계를 통과한다.
- 테스트에서는 실제 유료 API를 호출하지 않는다.

## 중지와 복구

- 진행 창을 닫아도 이미 시작한 백그라운드 작업은 중단하지 않는다.
- 중지는 아직 제출하지 않은 다음 장면부터 막는다.
- 이미 제출된 Provider Task는 계속 추적해 결과를 저장한다.
- Task ID, 입력 해시, 프로젝트 ID와 Scene 번호를 영구 저장한다.
- 성공한 장면은 재개 시 건너뛴다.
- 실패한 장면은 추가 비용을 다시 표시하고 사용자 승인 후 개별 재시도한다.
- **입력이 원인인 실패는 승인만으로 다시 사지 못한다.** 제공자가 그렇게 말한 코드(`INTERNAL.BAD_OUTPUT` ·
  `ASSET.INVALID`)면 화면도 서버도 **무엇을 바꿀지 적기 전까지 거절한다** — 같은 입력을 다시 보내면
  같은 실패를 다시 사기 때문이다. 안전 거절(`SAFETY.*`)은 첫 프레임이 원인이라 여기 안 걸린다:
  이미지를 다시 만들고 돌아오는 것이 정당한 경로다.
- 동일 입력의 성공 결과가 있으면 중복 요청을 차단한다.
- 자동 무한 재시도는 금지한다.

## 영상 검토와 병합

각 장면에서 원본 이미지, 최종 프롬프트, 생성 상태, 비용 기록과 영상을 확인할
수 있어야 한다. 모든 장면의 영상이 사용 확정돼야 FFmpeg 병합을 허용한다.

```text
videos/
├─ runway/       scene1.mp4 ... sceneN.mp4 (장면 수만큼)
├─ continuity/   scene1_last.png ... sceneN_last.png (장면 수만큼)
└─ final/        instagram_reel.mp4
```

기존 CapCut 파일은 자동 삭제하지 않지만 새 흐름에서는 사용하지 않는다.

## 캐릭터와 스타일

- 대표 캐릭터는 모든 장면에 등장한다.
- 기준 이미지를 모든 장면 이미지 생성에 사용한다.
- 얼굴, 머리, 기본 복장, 대표 색상과 고유 소품을 유지한다.
- 특정 작품이나 작가의 화풍을 복제하지 않는다.
- 참고 이미지는 색조, 조명, 구도, 배경과 소품 자료로만 사용한다.
- MVP에서는 PyTorch와 LoRA를 사용하지 않는다.

장기 프로젝트는 대표 캐릭터와 전체 그림체를 **작품 단위로 한 번** 고른다. 20화짜리에서
주인공을 20번 고를 이유가 없고, 서버가 그 선택을 모든 회차에 붙인다.

- 대표 캐릭터로는 **Asset 폴더만** 고를 수 있다. 캐릭터는 한 사람의 정면·옆·뒷모습 묶음이고
  낱장 그림은 그중 한 포즈다.
- **폴더 이름이 곧 주인공 이름이고, 그 이름이 회차 대본 프롬프트에 들어간다.** 따로 적는 칸은 없다.
- 이름은 저장할 때 복사하지 않고 프롬프트를 만들 때 읽는다. 보관함에서 폴더 이름을 고치면
  **다음 대본부터 반영된다.**
- 연결된 폴더를 읽을 수 없으면 이름 없이 대본을 만든다. 보관함 파일 하나가 유료 단계를 막지 않는다.

## 작품 설정 (장기 프로젝트)

장기 프로젝트는 회차마다 다시 정하지 않는 것들을 작품 단위로 한 번 적는다. 여기 적은 것은 회차를
나눌 때와 각 회차 대본을 만들 때 읽힌다 — **8화 반전을 8화에 가서 적으면 3·4·5화는 그것을 모른 채로
이미 만들어진 뒤다.**

- **세계관 설명**: 이름과 내용의 짝으로 적는다(예: `시대` → `20년 뒤 미래`).
- **비밀**: 무엇이 숨겨져 있는지와 **몇 화부터 써도 되는지**. 그 회차 전에는 대본 생성에
  "아직 쓰면 안 되는 정보"로 전달되고, 그 회차부터 "써도 되는 정보"가 된다. 비워 두면 1화부터다.
- **복선**: 아직 회수되지 않은 것이 대본 생성에 함께 전달된다.

등장인물·배경·소품은 글로 적지 않는다. 생김새는 이미지 보관함의 폴더로 정하고, 주인공은 위
"캐릭터와 스타일"의 규칙을 따른다.

## 단기 화면과 장편 화면의 대응

두 파이프라인은 **같은 일을 두 번 그린다.** 그래서 한쪽을 고치면 다른 쪽이 조용히 뒤에
남는다 — 실제로 세 번 그랬고(제목 띠 · 파이프라인 제목 · 헤더 부품), 한 번은 **12일** 걸려서
발견됐다. 고친 사람이 게을러서가 아니라, **대응이 어디에도 적혀 있지 않아서** 두 파이프라인을
다 아는 사람의 머릿속에만 있었기 때문이다.

셋째 칸이 이 표의 요점이다. **「마지막 대조」가 오래된 줄은 그 자체로 「여기 비대칭이 있을 수
있다」**는 뜻이다. 단기 화면을 고칠 때 그 자리에서 장편 짝을 확인하고 이 칸을 갱신한다 —
나중에 확인하는 순서는 그 자체가 잊히는 종류의 것이다.

🔴 **「대조」와 「일괄」을 구별해서 적는다. 이 구별이 없으면 셋째 칸은 거짓말을 한다.** 전
화면을 한 번에 훑는 작업은 짝을 **우연히** 같이 고친다 — 실제로 카드 제목 규격화(일괄)는
내레이션 확인 짝을 우연히 맞췄고, 바로 그 다음 작업(설정 화면, 한 화면씩)은 장편 짝을
놓쳐서 두 라운드 뒤에 따로 고쳐야 했다. **일괄에 같이 들린 것은 「이 둘이 맞는지 봤다」가
아니다.**

| 단기 화면 | 장편 대응 | 마지막 대조 |
|---|---|---|
| `ProjectList` | `LongProjectList` | 일괄 2026-09-09 |
| `CreateProjectForm` | `CreateLongProjectForm` | 일괄 2026-09-09 |
| `ProjectDetail` | `LongProjectDetail` | **대조** 2026-09-09 |
| `ShortProjectSettingsScreen` | `LongProjectSettingsScreen` | **대조** 2026-09-09 |
| `ShortProjectSettingsScreen` | `LongEpisodeSettingsScreen` (회차 단위) | 일괄 2026-09-09 |
| `StoryPromptScreen` | `LongEpisodeScriptScreen` | **대조** 2026-09-09 |
| `MappingReviewScreen` | **같은 부품** (`longEpisodeMappingReview` 가 그대로 쓴다) | — |
| `ImageGenerationScreen` | `LongEpisodeImageGenerationScreen` | **대조** 2026-09-09 |
| `NarrationReviewScreen` | `LongEpisodeNarrationReviewScreen` | 일괄 2026-09-09 |
| `VideoWorkflowScreen` | `LongEpisodeVideoWorkflowScreen` | **대조** 2026-09-09 |
| `VideoMergeScreen` | `LongEpisodeVideoMergeScreen` | **대조** 2026-09-09 |
| `VideoPromptPreviewScreen` | **없음** — 장편은 회차 단위 승인이 대신한다 | — |
| `SceneEditScreen` | **없음** — 장편은 회차 내용 화면(`LongEpisodeOutlineScreen`)이 대신한다 | — |
| `InstagramPostScreen` | **없음** — 발행은 단기에서만 한다 | — |
| **없음** | `LongProjectOutlineScreen` (회차 나누기) · `LongEpisodeContinuityScreen` (이어쓰기 메모) | — |

- 🟢 **`MappingReviewScreen` 줄이 제일 나은 모양이다** — 한 부품을 두 흐름이 쓰면 비대칭이
  **생길 수가 없다.** 나머지 줄에서 「왜 부품 하나로 못 하는가」를 물을 값어치가 있다.
- 🔴 **「없음」도 사실이고, 적혀 있어야 한다.** 안 적혀 있으면 다음 사람이 「빠뜨린 것」과
  「원래 없는 것」을 구별하지 못한다. `SceneEditScreen` 의 장편 짝을 찾다가 없다는 것을
  알아내는 데 드는 시간이 매번 다시 든다.
- 🟠 화면이 계속 움직이는 중이라 이 표는 낡을 수 있다. 낡은 표는 셋째 칸이 말해 준다 —
  **없는 표는 아무 말도 안 한다.**
- 🟠 **「합칠 수 있는가」는 이 표가 답해야 할 다음 질문이다.** `MappingReviewScreen` 이 하나로
  되는 이유는 「무엇에 대한 화면인가」가 **인자 하나 차이**(프로젝트냐 회차냐)라서다. 같은
  성질로 보이는 후보가 셋 있다 — 이미지 생성 · 영상 작업 · 영상 병합은 셋 다 「장면 묶음에
  대해 같은 일을 한다」이고 다른 것은 어느 묶음이냐뿐이다. 🔴 **반대로 대본 두 화면은 합치면
  안 된다**: 단기는 「없는 대본을 만든다」이고 장편은 「있는 개요에서 회차 대본을 쓴다」 —
  한 화면의 두 모드가 아니라 다른 단계다. 🟠 **이 문단은 코드를 읽은 짐작이고 재보지 않았다**
  (Cowork Round 694 ④). 합치기 전에 세 화면의 실제 차이를 재는 것이 먼저다.

## 현재 제외 범위

- 회원가입과 다중 사용자
- 서버 배포
- Instagram 실제 업로드
- PyTorch와 LoRA
- 승인 없는 자동 유료 생성
- 새로운 기능 추가

기존 Python 기능 이전이 완료되고 통합 검증을 통과한 후 제외 범위를 다시
검토한다.
