# Design System — Prism Forge (AI Animation Studio)

이 문서는 `apps/frontend` 의 모든 UI 작업에 적용되는 규격이다.
새 화면·컴포넌트를 만들거나 기존 화면을 수정할 때, 시각적 결정(색, 여백,
반경, 그림자, 타이포, 상태 표현)은 **이 문서에서 찾아 쓰고, 즉흥적으로
만들지 않는다.** 여기에 없는 패턴이 필요하면 먼저 이 문서에 항목을 추가한
뒤 구현한다.

- 스택 전제: Tailwind CSS v4 (`@import "tailwindcss"`), Inter, 다크 전용
  (`color-scheme: dark`), React + Vite, Electron 데스크톱 셸.
- 기존 화면과 이 문서가 다르면 **이 문서가 맞다.** 다만 리팩터링을 위한
  일괄 수정은 하지 말고, 해당 화면을 다른 이유로 만질 때 규격으로 옮긴다
  (surgical changes 원칙 유지).

---

## 1. 디자인 원칙

1. **작업 도구다.** 이 앱은 감상용 랜딩페이지가 아니라 장면 파이프라인을
   반복 실행하는 제작 도구다. 화려함보다 "지금 어느 단계이고, 다음에 뭘
   해야 하는가"가 항상 먼저 읽혀야 한다.
2. **빛은 아껴 쓴다.** violet 글로우는 브랜드 시그니처지만, 화면당 시선을
   끄는 발광 요소는 1~2곳(주 CTA, 현재 단계 표시)으로 제한한다. 모든 것이
   빛나면 아무것도 눈에 띄지 않는다.
3. **상태색은 문법이다.** emerald=완료/성공, amber=진행 중/주의,
   rose=실패/오류, violet=현재 위치/선택. 이 매핑을 다른 의미로 재사용하지
   않는다.
4. **돈이 걸린 화면은 조용하게.** 비용 확인·전송 승인 화면에서는 장식을
   줄이고 숫자와 승인 버튼이 지배하게 한다. 유료 요청 버튼 주변에 시선을
   분산시키는 요소를 두지 않는다.

## 2. Foundation

### 2.1 색

배경 레이어 (어두운 순):

| 역할 | 클래스 |
|---|---|
| 앱 배경 | `bg-slate-950` (+ §5.1의 배경 그라데이션, App 셸에서만) |
| 화면 안 우묵한 면 (썸네일 트레이, 코드/로그 영역) | `bg-slate-950/40` |
| 카드·패널 표면 | `bg-slate-900/70` |
| 사이드바 | `bg-slate-900` |
| 입력 필드 | `bg-slate-900/70` |
| 채워진 트랙(프로그레스 바탕, 스켈레톤) | `bg-slate-800` |

테두리: 기본은 항상 `border-white/10`. 상태 강조 시에만
`border-{색}-400/40` (아래 상태색 표 참조).

텍스트 위계 (4단계만 사용):

| 역할 | 클래스 |
|---|---|
| 제목·강조 | `text-slate-100` (또는 `text-white` — 활성 항목만) |
| 본문 | `text-slate-300` |
| 보조 설명·레이블 | `text-slate-400` |
| 비활성·자리표시 | `text-slate-500` |

`text-slate-200`은 쓰지 않는다 (위계가 흐려진다).

브랜드 액센트:

| 역할 | 클래스 |
|---|---|
| 주 CTA 그라데이션 | `from-violet-500 to-fuchsia-500` |
| 히어로/제목 그라데이션 텍스트 | `from-violet-300 to-pink-300` (bg-clip-text) |
| 활성 네비·선택 배경 | `bg-violet-500/15` + `text-white` |
| 네비 기본 텍스트 | `text-violet-300` |
| 장식 점(dot)·포커스 링 | `bg-violet-400`, `ring-violet-500/30` |
| **끝난 것 한 곳의 강조** | `bg-gold` / `text-gold-ink` (`goldButton`, 2026-09-14 톤 B) |

**금색(`--color-gold: #e8c27a`, `--color-gold-ink: #2b1d09` — `styles.css` 의
`@theme`)은 액센트지 상태색이 아니다.** 완성·최종본·게시처럼 「끝났다」는 자리
**한 곳의 버튼 하나**에만 쓴다. 화면에 둘째 금색이 생기면 그건 강조가 아니라
팔레트가 된 것이니 위 보라·핑크로 돌아간다.

- 🔴 **상태 표시에는 쓰지 않는다.** §6 의 「색만으로 상태를 말하지 않는다」가
  그대로 적용된다 — 금색은 장식이고, 상태는 `StatusChip` 의 **글자**가 말한다.

상태색 (의미 고정):

| 상태 | 텍스트 | 테두리 | 배경(칩/배너) |
|---|---|---|---|
| 성공·완료 | `text-emerald-300` | `border-emerald-400/30` | `bg-emerald-500/10` |
| 진행 중·주의 | `text-amber-300` | `border-amber-400/40` | `bg-amber-500/10` |
| 실패·오류 | `text-rose-400` | `border-rose-400/30` | `bg-rose-500/15` |
| 현재 위치·선택 | `text-violet-300` | `border-violet-400/50` | `bg-violet-500/15` |
| **정보·알아 두실 것** | `text-sky-300` | `border-sky-400/30` | `bg-sky-500/10` |

**정보 칸은 2026-09-09에 추가됐다. 색을 고른 것이 아니라, 이미 있던 것을
인정한 것이다.** 이 표에 정보 칸이 없던 동안 네 화면(설정집과 다른 점,
개요·이어쓰기 메모 없음, 단계 안내, Instagram 안내)이 **각자 따로 `sky` 를
찾아냈다** — 22곳. 같은 뜻을 여러 화면이 독립적으로 같은 색으로 적으면,
그건 규칙 위반이라기보다 **표에 칸이 하나 비어 있다는 신호**다.

- 🔴 **기계적으로 옮기면 뜻이 바뀐다.** amber 로 보내면 「주의하세요」가
  되는데 설정집과 다른 점은 주의가 아니라 정보고, violet 로 보내면 「현재
  위치」와 부딪힌다. slate 로 낮추면 알림 넷이 배경으로 가라앉는다.
  **비어 있던 것은 색이 아니라 뜻이었다.**
- 🔴 **그래서 `sky` 는 이 칸에서만 쓴다.** 장식으로는 여전히 금지다(§7).
  §7 이 `sky`·`teal`·`lime` 을 막은 이유는 화면이 기분에 따라 색을
  만들어 내는 것을 막기 위해서고, **뜻이 고정된 칸 하나는 그 이유에
  해당하지 않는다.**
- 🟠 **표기는 위 세 값으로 통일한다.** 지금 코드에는 `text-sky-200`,
  `text-sky-100`, `bg-sky-500/[0.06]`, `border-sky-400/20`, `/25`, `/45`
  처럼 열 가지 표기가 섞여 있다 — 칸이 문서에 없는 동안 각자 정한 값들이다.
  다른 네 상태와 같은 문법으로 맞춘다.

- 원색 배경(`bg-amber-500`, `bg-violet-500` 등)은 작은 인디케이터(점, 채움
  바)에만 허용. 넓은 면에는 항상 `/10~/15` 투명 배경을 쓴다.

### 2.2 타이포그래피

| 역할 | 클래스 |
|---|---|
| 화면 제목 (화면당 1개) | `text-2xl font-semibold text-slate-100` |
| 섹션 제목 | `text-lg font-semibold text-slate-100` |
| 카드 제목·항목명 | `text-sm font-semibold text-slate-100` |
| 본문 | `text-sm text-slate-300` |
| 보조·메타 | `text-xs text-slate-400` |
| 브랜드 워드마크 | `text-xs font-semibold uppercase tracking-[0.24em] text-violet-400` |

- `text-base`는 쓰지 않는다. 본문은 `text-sm`으로 통일 (데스크톱 도구 밀도).
- `font-bold`는 쓰지 않는다. 강조는 `font-semibold`까지.
- 숫자 데이터(비용, 진행 수치)에는 `tabular-nums`를 붙인다.

**제목 앞 앵커** (2026-09-09 추가). 제목은 시선이 걸리는 표식을 하나 갖는다.
어느 표식이냐는 위계로 정해져 있고, 화면이 고르는 것이 아니다:

| 역할 | 앵커 | 클래스 |
|---|---|---|
| 화면 제목 (h1) | 발광하는 점 **하나** | `h-2 w-2 rounded-full bg-gradient-to-br from-violet-300 to-pink-300` + glow-dot |
| 섹션 제목 (h2) | 그라디언트 막대 | `h-4 w-1 flex-shrink-0 rounded-full bg-gradient-to-b from-violet-400 to-fuchsia-400` |
| 카드 제목 (h3) | 같은 막대, 짧게 | `h-3 w-1 flex-shrink-0 rounded-full bg-gradient-to-b from-violet-400 to-fuchsia-400` |

- 제목 줄은 `flex items-center gap-2.5` 로 감싼다. 앵커는 전부 `aria-hidden="true"` —
  장식이지 이름이 아니다(§6).
- 🔴 **막대에는 그림자를 붙이지 않는다.** 발광하는 점은 **화면당 하나(h1)** 다.
  h3 가 일곱 개인 화면에서 점을 일곱 개 켜면 §1 원칙 2 그대로 아무것도 눈에
  안 띈다. 막대는 앵커의 역할만 하고 §2.5 의 글로우 3개에 넷째를 더하지 않는다.
- 상태색을 갖는 제목(진행 중·오류 등)은 그 색이 뜻을 나르므로 위 표에서 제외한다.

### 2.3 간격

4px 격자.

세 단계다. 무엇과 무엇을 벌리는지가 값을 정한다 — 취향으로 고르지 않는다.

| 무엇 사이 | 값 | 예 |
|---|---|---|
| 컴포넌트 내부의 작은 요소 | `gap-2` `gap-3` / `space-y-2` `space-y-3` | 라벨과 입력, 버튼 행, 목록 항목 |
| 카드·패널 **안**의 블록 | `space-y-4` | `rounded-2xl … p-5` 또는 `p-6` 안에서 문단·필드 묶음 사이 |
| 화면 섹션 사이 | `space-y-5` 또는 `mt-6` | `mt-8 max-w-* space-y-5` 화면 본문, 카드끼리 |

- 카드 패딩: 작은 카드 `p-3`~`p-4`, 큰 패널·폼 `p-6`
- 🔴 `space-y-4` 를 화면 본문 래퍼에 쓰지 않는다. 화면 본문은 `space-y-5` 다 —
  2026-09-06 에 세 화면(`App` 명언 건너뜀 안내 · `ProviderSettingsScreen` ·
  `LongProjectSettingsScreen`)이 `space-y-4` 로 어긋나 있었고, 나머지 스무 화면은
  전부 `space-y-5` 였다. 카드 안이 `space-y-4` 인 것은 어긋난 게 아니라 위 표의
  둘째 줄이다 — 열세 군데가 같은 규칙을 쓰고 있었는데 이 문서에만 없었다.
- 화면 제목 아래: `mt-6`, 큰 블록 전환: `mt-8`
- 본문 컨테이너: `max-w-3xl` (폼은 `max-w-xl`), 메인 패딩 `px-12 py-12`

### 2.4 모서리 반경 (3단계로 고정)

| 용도 | 클래스 |
|---|---|
| 카드·패널·폼·다이얼로그 | `rounded-2xl` |
| 카드 내부 항목·입력 필드·썸네일·중첩 박스 | `rounded-xl` |
| 버튼(필/고스트)·칩·배지·점·바 | `rounded-full` |

`rounded-lg`는 신규 코드에서 쓰지 않는다 (기존 코드 수정 시 `rounded-xl`로).
예외: 사이드바 네비 항목은 `rounded-lg` 유지 (좁은 영역 밀도).

### 2.5 그림자와 글로우

임의값 `shadow-[...]`를 매번 새로 만들지 않는다. 아래 3개만 사용:

| 이름 | 값 | 용도 |
|---|---|---|
| glow-cta | `shadow-[0_0_16px_rgba(139,92,246,0.35)]` | 주 CTA 버튼 |
| glow-dot | `shadow-[0_0_6px_rgba(216,180,254,0.7)]` | 장식 점, 스피너 링 |
| glow-bar | `shadow-[0_0_8px_rgba(139,92,246,0.6)]` | 진행 바 채움 |

제목 앞 그라디언트 막대(§2.2)는 **글로우가 아니다** — 그림자가 없다. 넷째
글로우를 추가한 것으로 읽지 않는다.

이 외의 글로우가 필요해 보이면 원칙 2를 다시 읽는다. 일반 elevation
그림자(shadow-md 등)는 다크 배경에서 효과가 없으므로 쓰지 않는다 —
층위는 배경색 단계와 테두리로 표현한다.

### 2.6 모션

- 트랜지션은 `transition-colors duration-150` 을 기본으로, hover/active
  색 변화에 건다.
- 로딩 회전은 `animate-spin`(Spinner 컴포넌트)만 사용.
- 새로 뜨는 패널·다이얼로그는 애니메이션 없이 즉시 표시 (도구 반응성 우선).

**2026-09-14 정정 — 「레이아웃이 움직이는 애니메이션은 금지」를 좁혔다.**
톤 B(§3.9)가 들어오면서 목록 카드가 등장할 때 10px 올라오고, 버튼이 hover 때
0.5 뜬다. 금지 자체를 지운 것이 아니라 **어디까지가 금지인지**를 적는다.

| | |
|---|---|
| 허용 | **한 번 일어나고 끝나는 것** — 카드 등장(§3.9 다), hover 로 사람이 부른 것(버튼 뜸·빛 스침) |
| 허용 | **지금 실제로 돌아가는 중**임을 말하는 무한 반복(§3.9 라) |
| 🔴 금지 | 이미 떠 있는 것의 **내용이 바뀔 때** 다시 도는 등장 애니메이션 — 「새로 생긴 것」으로 읽힌다 |
| 🔴 금지 | 멈춰 있는 것 위의 무한 반복 — 「기다리면 된다」로 읽힌다 |
| 🔴 금지 | 못 누르는(`disabled`) 버튼이 hover 에 반응하는 것 — 눌린 줄 안다 |

- **전부 `prefers-reduced-motion: reduce` 에서 꺼진다.** 끄는 것이 화면을
  **비우면 안 된다** — 등장 애니메이션은 `opacity-0` 에서 시작하므로
  `motion-reduce:opacity-100` 을 반드시 같이 단다(§3.9 마).

## 3. 컴포넌트 레시피

**이미 있는 공용 컴포넌트(`Spinner`, `WorkflowProgressBar`)는 반드시
재사용한다.** 아래 레시피를 세 곳 이상에서 반복하게 되면 그때
`components/ui/` 로 추출한다 (미리 추상화하지 않는다).

### 3.1 버튼

주 CTA (화면당 1개, 파이프라인을 전진시키는 행동):
```
rounded-full bg-gradient-to-r from-violet-500 to-fuchsia-500 px-5 py-2.5
text-sm font-semibold text-white shadow-[0_0_16px_rgba(139,92,246,0.35)]
hover:from-violet-400 hover:to-fuchsia-400 disabled:opacity-50
disabled:pointer-events-none
```

보조 버튼 (취소, 뒤로, 부가 행동):
```
rounded-full border border-white/10 px-5 py-2.5 text-sm text-slate-300
hover:bg-white/5 disabled:opacity-50
```

위험 버튼 (삭제, 중단 — 확인 다이얼로그와 함께):
```
rounded-full border border-rose-400/30 bg-rose-500/15 px-5 py-2.5
text-sm font-semibold text-rose-300 hover:bg-rose-500/25 disabled:opacity-50
```

작은 인라인 버튼 (카드 안의 재생성·수정 등):
```
rounded-full border border-white/10 px-3 py-1.5 text-xs text-slate-300
hover:bg-white/5
```

규칙:
- 그라데이션 CTA가 한 화면에 2개 이상 보이면 잘못된 것이다. 하나만 남기고
  나머지는 보조 버튼으로 내린다.
- **유료 요청을 전송하는 버튼은 반드시 주 CTA 스타일**이고, 라벨에 행동과
  대상을 명시한다 ("영상 N개 생성 전송" — "확인" 같은 모호한 라벨 금지).
- 로딩 중 버튼은 라벨을 진행형으로 바꾸고 (`생성 중...`) disabled 처리.

### 3.2 입력 필드

```
mt-1.5 w-full rounded-xl border border-white/10 bg-slate-900/70 px-3.5
py-2.5 text-sm text-slate-100 placeholder:text-slate-500
focus:border-violet-400/50 focus:outline-none focus:ring-2
focus:ring-violet-500/30 disabled:opacity-50
```

- 레이블: `block text-sm text-slate-300` + `htmlFor`.
- 필드 오류: 필드 바로 아래 `mt-1.5 text-sm text-rose-400` + `role="alert"`.
- textarea도 동일 규격 (+`resize-y`).
- `select`도 같은 입력 표면을 사용한다. 네이티브로 열리는 선택 목록은 전역에서
  다크 색 체계(`color-scheme: dark`)를 강제하고, 항목은 `bg-slate-900`과
  `text-slate-100` 대비를 유지한다. OS 기본의 흰 목록을 그대로 두어 다크 화면의
  선택 항목이 읽히지 않게 만들지 않는다.

### 3.3 카드·패널

🔴 **클래스 문자열을 손으로 적지 않는다. `apps/frontend/src/components/ui/surfaces.ts`
에서 가져온다** (§3.8). 아래는 그 파일이 무엇을 담고 있는지에 대한 설명이지,
베껴 쓰라고 있는 것이 아니다 — 손으로 베낀 사본 19개가 서로 어긋난 것이
이 파일이 생긴 이유다.

기본 카드 (섹션 패널, 폼 컨테이너) — `cardSection`:
```
space-y-3 rounded-2xl border border-white/10 bg-gradient-to-b from-slate-900/80 to-slate-900/55 p-5
```
- `cardSectionWide` = 같은 표면에 `space-y-4` (행이 글이 아니라 컨트롤일 때)
- `cardSectionRoomy` = 같은 표면에 `space-y-4 p-6` (카드 한 장이 화면 전체의 주제일 때)

🟠 **평면 `bg-slate-900/70` 에서 세로 그라디언트로 바뀌었다** (2026-09-09).
카드가 여러 장 쌓일 때 한 덩어리로 읽히던 것을 갈라 놓기 위해서다. **색은 안
늘었다** — 위아래 다 `slate-900` 이고 투명도만 다르다(§7 위반 아님).

내부 항목 카드 (장면 하나, 목록 항목):
```
rounded-xl border border-white/10 bg-slate-950/40 p-3
```
안쪽 카드는 평면 그대로다. 그라디언트는 **바깥 카드끼리 갈라 보이게** 하려는
것이고, 안쪽까지 주면 그 대비가 사라진다.

상태 강조 카드: 기본 카드에서 테두리만 상태색으로 교체
(예: 진행 중 장면 `border-amber-400/40`). 배경은 바꾸지 않는다.

### 3.4 상태 칩 (배지)

**구현체: `components/ui/StatusChip.tsx` — 새로 만들지 말고 이걸 쓴다.**
(장면 진행 그리드·이미지 검토·영상 검토 3곳 이상에서 반복되어 §3 규칙대로 추출했다.)

```tsx
<StatusChip tone="success">확정됨</StatusChip>
```

`tone`은 §2.1 상태색 문법과 1:1로 대응하며 다른 의미로 재사용하지 않는다:

| tone | 의미 | 색 |
|---|---|---|
| `success` | 완료·확정 | emerald |
| `progress` | 진행 중·주의 | amber |
| `danger` | 실패·오류 | rose |
| `neutral` | 대기·미시작, 또는 알릴 것이 없음 | 무채색 |
| `info` | 정보·알아 두실 것 | sky |

내부 클래스(직접 쓸 일 없음):
```
inline-flex items-center gap-1.5 rounded-full border px-2.5 py-0.5
text-xs font-semibold
```
+ §2.1 상태색 표의 텍스트/테두리/배경 3종 세트.
칩 안 점: `h-1.5 w-1.5 rounded-full bg-current`.
라벨 텍스트는 항상 렌더한다 — 상태를 색으로만 전달하지 않는다(§6).

워크플로우 상태 ↔ 칩 매핑: COMPLETED→성공 / GENERATING_*, RENDERING→진행 중
/ FAILED, CANCELLED→실패 / INTERRUPTED→주의(amber) / 대기·검토 단계→중립
(`border-white/10 text-slate-300`).

**`info` 는 2026-09-11 에 추가됐다. §2.1 에 「정보·알아 두실 것」 칸이 생긴 것은
2026-09-09 인데 이 표에는 이틀 동안 그 칸이 없었고, 그동안 그 뜻이 필요했던 첫 화면
(생성 출처 배지)이 `StatusChip` 을 통째로 베껴 자기 알약을 그렸다.** 베낀 쪽은
`paid_provider` 에 완료색(emerald)을 줬고, 그 배지는 이미지 검토 화면에서 장면의
`StatusChip` 과 **같은 줄에** 놓인다 — 확정된 장면 하나에 초록 알약이 둘, 뜻은 서로
달랐다. 부품에 칸이 없으면 다음 사람은 규칙을 어기는 게 아니라 **부품을 복제한다.**

**`neutral` 은 같은 날 뜻을 넓혔다.** 출처 배지의 `paid_provider` 가 갈 곳이 필요했는데,
「실제 생성」은 완료도 주의도 정보도 아니고 그냥 **알릴 것이 없는 상태**다. 색은 그대로
무채색이다.

**`active` 는 2026-09-11 에 이 표에서 뺐다 — 구현하지 않기로 정한 것이다**
(근거: `docs/06_DECISIONS.md` D-050). §2.1 의 violet 「현재 위치·선택」 칸은
**그대로 있다.** 빠진 것은 색이 아니라 **칩이 그것을 그린다는 주장**이다.
그 뜻은 이 앱에서 언제나 **누를 수 있는 것**이 갖는다 — 사이드바 항목(`App.tsx`),
`StepRibbon` 의 현재 단계, 고르는 칸들(`SceneEditScreen`·`SceneSubtitleFieldset`·
`WorkflowGuideScreen`) — 여섯 곳 전부 §3.2 「활성 네비·선택 배경」 쪽이고 칩이 아니다.
`StatusChip` 은 **항목이 어떤 상태인지**를 읽는 것이라 눌리지 않는다.

### 3.5 오류·안내 배너

인라인 문장 오류(폼)는 §3.2 방식. 화면 수준 오류는 배너로:
```
rounded-xl border border-rose-400/30 bg-rose-500/15 p-4 text-sm
text-rose-300  (+ role="alert", data-error-code 유지)
```
안내·주의 배너는 amber 세트로 동일 구조. 성공 확인은 emerald 세트.

**막는 오류는 「어디서 어떻게 고치는지」까지 말한다(2026-10-10, 뉴스 릴).** 「기사에서 못 찾은 것」 붉은 줄은 문제의 글만 적어 두어 사람이 어느 칸인지 몰라 릴을 못 만들고 서 있었다. 이제 각 항목 옆에 그 글이 있는 칸(「1번 장면 자막」)을 적고, 고치는 법을 한 문단으로 말하며, 따옴표로 감싼 말에만 「따옴표 빼기」(인용 표시만 걷고 말은 그대로)를 준다. 숫자·날짜는 뜻이 바뀌므로 자동 수정 없이 칸만 알린다. 대조 자체(`checkNewsSummary`, 서버 동일)는 약하게 만들지 않는다.

**입력칸 위 조건 문구(API 키 칸 등, 2026-10-09):** 상자·주황 글씨로 쓰지 않는다. `border-l-2 border-amber-400/40 pl-3 text-xs text-slate-400` — 얇은 세로선과 차분한 글자. 문장은 입력칸 바로 위에 항상 보이고(조건이라 접지 않는다) 입력칸보다 눈에 띄지 않게 한다. 상태 표시는 점 + 글자(`bg-emerald-400`·`bg-amber-400`·`bg-slate-500`)를 카드 제목 오른쪽 한 줄에 둔다.

### 3.6 로딩·빈 상태

- 인라인 로딩: 기존 `<Spinner label="..."/>` 사용. 새 스피너를 만들지 않는다.
- 목록 빈 상태: 내부 항목 카드 규격 + 중앙 정렬, 두 줄 구성 —
  `text-sm text-slate-300` 안내 + 필요 시 작은 인라인 버튼. 일러스트 금지.
- 스켈레톤: `animate-pulse rounded-xl bg-slate-800` 블록. 텍스트 자리에는
  높이 `h-4`, 썸네일 자리에는 실제 비율.

### 3.7 다이얼로그 (확인·아카이브 등)

- 오버레이: `fixed inset-0 bg-slate-950/70`
- 패널: `w-full max-w-md rounded-2xl border border-white/10 bg-slate-900
  p-6 space-y-4` (불투명 배경 주의 — /70 아님)
- 제목 `text-lg font-semibold text-slate-100`, 본문 `text-sm text-slate-300`,
  버튼 행은 `flex justify-end gap-3 pt-2`, 파괴적 행동이면 위험 버튼 사용.
- `role="dialog"` `aria-modal="true"` `aria-labelledby` 필수. 열릴 때 첫
  버튼으로 포커스 이동, Esc로 닫기.

### 3.8 공유 부품 (`apps/frontend/src/components/ui/`)

레시피를 **문서에서 읽어 베끼는 것**과 **부품에서 가져다 쓰는 것**은 다르다.
베낀 사본은 갈라진다 — 실제로 갈라졌다(§3.3, §4.1). 아래가 있는 것은 이제
클래스 문자열을 새로 적을 이유가 없다는 뜻이다.

| 부품 | 무엇인가 |
|---|---|
| `ScreenHeader.tsx` | 화면 상단 띠 — h1, 뒤로가기, 설명, 화면 단위 액션. §4.1 의 골격을 이것이 그린다 |
| `Panel.tsx` | 카드 한 장. `tone` 으로 §3.4 의 **뜻**을 고른다(색을 고르는 것이 아니다) |
| `StepRibbon.tsx` | 파이프라인 띠 — "6단계 중 4단계"를 답한다 |
| `surfaces.ts` | §3.1 버튼 3종, §3.3 카드 표면 3종, `scrollList`(아래), 그리고 §3.9 의 `goldButton`·`riseInCard`·`pulseDot` 의 클래스 문자열 |

- 🔴 **`ScreenHeader` 의 화살표는 부품이 그린다.** 호출부는 **말만** 넘긴다
  (`backLabel="프로젝트 목록으로"`). 화살표를 라벨 문자열에 넣으면 접근성
  이름 안으로 들어가 스크린 리더가 "왼쪽 화살표 …"로 읽고(§6 위반), 동시에
  **호출부가 잊을 수 있는 장식**이 된다 — 21곳 중 10곳이 실제로 잊었다.
  장식은 부품이 갖는다.
- 🔴 **`Panel` 의 `tone` 은 §3.4 의 의미 목록이고 팔레트가 아니다.** 화면이
  변화를 주고 싶어서 고르는 값이 아니다. 그리고 tone 이 쓰는 색은 §7 의
  허용 팔레트 안에 있어야 한다 — 새 tone 을 추가할 때 여기가 먼저다.
- 🔴 **길이를 사용자가 정하지 않는 목록에는 `surfaces.ts` 의 `scrollList` 를 쓴다**
  (`max-h-64 space-y-1 overflow-y-auto pr-1`). 보관함 전체를 훑는 검색 결과나
  「지금까지 만든 프로젝트 전부」 같은 목록이다. 2026-09-11 에 캡틴D가 분위기 이미지를
  고르다 막혔다 — 검색이 **84개**를 돌려주고 한 줄씩 세로로 쌓아서 목록 하나가
  **4,588px**이 됐고, 검색창과 그 아래 모든 항목이 화면 밖으로 밀려났다. 내용이 틀린 게
  아니라 **천장이 없었다.**
  - 🟠 **사용자가 직접 고른 목록은 덮지 않는다.** 선택된 분위기·장면 참고 이미지처럼
    길이가 본인 행동의 결과인 목록은 그대로 둔다. 자기가 고른 것을 접어 숨기는 것은
    더 나쁜 문제다.
  - `AssetLibraryScreen` 의 「에셋 목록」은 같은 모양을 손으로 갖고 있고 **일부러 더
    높다** — 그 목록은 폼 안의 한 칸이 아니라 화면 전체의 주제다. 그래서 부품으로
    바꾸지 않았다.
- 새 부품을 `ui/` 에 추가하면 **이 표에 줄을 더하는 변경을 같은 작업에
  포함**한다(§8-2 와 같은 규칙).

### 3.9 톤 B — 액센트와 모션 (2026-09-14)

캡틴D가 룩북 두 안(A: 소개형, B: 효과 중심 대시보드형) 중 **B** 를 골랐다.
순수 프론트이고 백엔드와 무관하다. 클래스 문자열은 `components/ui/surfaces.ts`,
키프레임과 `::after` 가 필요한 둘은 `styles.css` 에 있다.
**새 클래스를 붙인 요소만 바뀐다** — 안 붙인 화면은 그대로다.

**(가) 금색 버튼 — `goldButton`** (`surfaces.ts`)
- §2.1 의 `gold`·`gold-ink` 토큰을 쓰는 버튼. **한 화면에 하나.**
- 쓰는 곳: 완성·최종본·게시처럼 「끝났다」는 자리의 강조 버튼 하나.
- 🔴 쓰지 말 곳: 상태 표시(§2.1 의 🔴), 그리고 주 CTA 자리 — 주 CTA 는
  §3.1 의 보라·핑크 그라데이션 하나뿐이다. 금색이 그 옆에 서면 화면에
  **주인공이 둘**이 된다.

**(나) 버튼 hover — `outlineButton`·`primaryButton`·`secondaryButton`**
- 셋 다 hover 때 `-translate-y-0.5` 로 살짝 뜬다. 색·구조는 안 바뀌었다.
- 🔴 `disabled:hover:translate-y-0` 이 셋 다에 붙어 있다 — **못 누르는 버튼이
  반응하면 눌린 줄 안다.** 새 버튼을 더할 때 이 짝을 빠뜨리지 않는다.

**(다) 카드 등장 — `riseInCard`** (`surfaces.ts`) + `@keyframes rise-in` ·
`.effect-card` (`styles.css`)
- 10px 아래에서 0.45s 올라오며 나타나고, 그 뒤로는 완전히 정지한다. hover 때
  대각선 빛이 **한 번** 지나간다(`.effect-card::after`, 무한 반복 아님).
- 여러 장이면 `style={{ animationDelay: Math.min(index, 8) * 60 + "ms" }}` 로
  차례차례. 🔴 **8번째에서 멈춘다** — 상한이 없으면 50개짜리 목록의 끝이
  3초 뒤에 나타난다.
- 쓰는 곳: 목록 카드 한 장(프로젝트·영상·에피소드 행).
- 🔴 쓰지 말 곳: **이미 떠 있는 것의 내용이 바뀔 때**(§2.6 의 금지).
- 🟠 붙이는 자리: 카드 자체가 `rounded-*` 인 `<button>` 이면 `<li>` 가 아니라
  **그 `<button>` 에** 붙인다. `.effect-card` 의 `overflow:hidden` 이 모서리와
  어긋나서 빛이 각지게 잘린다.

**(라) 진행 중 표시 — `.bar-live`** (`styles.css`) · **`pulseDot`** (`surfaces.ts`)
- `.bar-live`: 진행 바 위를 빛이 계속 지나간다(무한 반복).
  `WorkflowProgressBar` 가 **`workflowStateTone(state) === "progress"` 이고
  실패가 아닐 때만** 붙인다.
- `StatusChip` 의 점은 `tone === "progress"` 일 때만 깜빡인다.
- 🔴 **둘 다 「지금 실제로 돌아가는 중」에만.** 멈춘 것 위에서 계속 흐르면
  기다리면 된다고 읽는다.
- 🔴 **진행 중인지 아닌지는 `workflowStateTone` 하나가 정한다.** 상태 목록을
  두 군데 두면 언젠가 서로 달라진다 — 이 저장소가 이미 여러 번 겪은 모양이다.
- 점은 **보조**다. 상태는 칩의 **글자**가 말하고 점은 거들 뿐(§6).

**(마) 안 움직이기**
- 위 전부 `@media (prefers-reduced-motion: reduce)` 에서 꺼진다.
- 🔴 `riseInCard`·`pulseDot` 은 클래스 자체에 `motion-reduce:` 가 붙어 있다.
  `riseInCard` 는 `opacity-0` 에서 시작하므로 `motion-reduce:opacity-100` 이
  없으면 **꺼진 순간 카드가 안 보인다.** 등장 애니메이션을 새로 만들면 이
  짝이 먼저다.

### 3.10 명언 카드 자막 — 영상에 굽는 글자 (2026-10-05)

앱 화면이 아니라 **영상에 구워지는 글자**의 규칙이다. 앱 UI 의 §2.5 그림자 금지와는 별개다 — 사진 위
글자는 그림자 없이는 읽히지 않는다. 수치는 전부 `packages/shared/src/domain.ts` 의 공유 상수이고, 렌더
(`subtitle-file.ts`)와 설정 화면 미리보기(`PhotoCardSubtitleFieldset.tsx`)가 **같은 상수를 읽는다**. 여기에
숫자를 다시 적지 않는다 — 두 번 적힌 숫자는 갈라진다.

| 겹 | 상수 | 하는 일 |
|---|---|---|
| 얇은 윤곽 | `PHOTO_CARD_SUBTITLE_OUTLINE` | 글자 가장자리를 또렷하게. 두껍게 하지 않는다 — 스티커처럼 뜬다 |
| 후광 | `…_GLOW_BORDER_RATIO`, `…_GLOW_BLUR_RATIO`, `…_GLOW_ALPHA` | 테두리색으로 번지는 어두운 빛. 글자를 사진 속에 녹인다 |
| 아래 그림자 | `…_DROP_Y_RATIO`, `…_DROP_ALPHA` | 바로 아래로만 떨어지는 부드러운 그림자. 무게감 |
| 제목 자간 | `…_QUOTE_SPACING_RATIO` | 사자성어 줄만 넓힌다. 본문은 0 |

- 비율은 그 줄의 **ASS 크기**(프레임 좌표)에 곱한다. 제목과 본문은 크기가 달라 값도 다르다.
- 색은 정하지 않는다 — 그림에서 뽑은 팔레트(`card-palette.ts`)의 테두리색이 윤곽·후광·그림자의 색이다.
- ASS 알파 바이트는 0 이 불투명이다. CSS 불투명도로 옮길 때는 `(255 - alpha) / 255`.
- 미리보기는 CSS `text-shadow` 를 쌓은 **근사**다(libass 의 획 테두리를 CSS 는 못 그린다). 근사라는 사실은
  미리보기 화면이 이미 말하고 있다. 정착 프레임만 그린다 — 등장 번개 효과는 렌더에만 있다.
- 뉴스 릴·일반 장면 자막에는 적용하지 않는다.

#### 첫 사진 효과와 어두워짐 (Cowork 1182·1189)

- 「효과」는 `select`(§3.2 입력 표면)로 고른다. 목록은 공유 `PHOTO_CARD_EFFECTS`, 화면 말은 번개 / 없음.
  값이 없는 옛 카드는 `DEFAULT_PHOTO_CARD_EFFECT`(번개)로 보이고, **사람이 고르면 항상 명시해서 보낸다** —
  생략은 서버에서 번개라, 「없음」을 고른 사람을 조용히 되돌린다.
- 번개는 파랑 계열을 쓰지 않는다: 흰 핵심선 + 따뜻한 흰 안쪽 빛 + 호박빛 바깥 빛. 화면 전체 섬광은 약하게,
  밝음은 번개 줄기 주변에 모은다(전체를 희게 덮으면 안개처럼 보인다).
- 「번개 뒤 어두워짐」은 range 슬라이더. 범위·단계·기본값은 공유 `PHOTO_CARD_DARKENING` 하나에서 읽고,
  값이 없는 옛 카드는 기본값으로 본다. 효과가 「없음」이면 어두워질 일이 없으므로 **칸 자체를 숨긴다**.
- 「지금 영상의 값으로」·「기본값으로」 비교는 크기·위치·효과·어두워짐을 모두 본다(없는 값은 기본값으로
  읽고 비교). 「기본값으로」는 크기·위치·어두워짐만 공장값으로 돌리고 **고른 효과는 남긴다**.
- 미리보기 상자는 정착 프레임만 그린다. 움직임은 무료 움직임 미리보기에서 본다는 것을 효과 설명 줄이 말한다.

#### 배경 효과 — 우주·빛줄기·파도 (CLI 1263·1265)

- 목록 순서는 공유 계약 그대로: 번개 / 우주 / 빛줄기 / 파도 / 없음. 기본값(번개)이 맨 앞, 「없음」이 맨 끝.
  화면 말은 프론트 `EFFECT_LABEL` 에만 둔다(계약에는 값만).
- **위계: 배경은 크기와 움직임으로 눈을 끌고, 글자는 처음부터 읽힌다.** 새 효과는 첫 인용 프레임과 함께
  시작하므로 글자가 배경을 기다리지 않는다. 효과 설명 줄(`photo-card-subtitle-effect-note`)이 효과마다 한 줄로
  무엇이 움직이는지와 「글자는 처음부터 함께 보인다」를 말한다. 범위는 첫 사진뿐.
- 「번개 뒤 어두워짐」 칸은 **번개 전용**으로 유지한다. 서버가 새 효과에서 `darkening` 을 쓰지 않으므로,
  칸을 보이면 효과 없는 손잡이가 된다.
- 움직임 미리보기는 효과까지 굽는다. 그래서 미리보기의 「낡음」 판정(`merge-still-motion-preview-stale-layout`)은
  크기·위치뿐 아니라 효과·어두워짐 변화도 본다(빈 값은 기본값으로 읽어, 없음→번개 같은 같은 뜻의 변화는 낡음이 아니다).

#### 사진 카드·뉴스 릴의 한 장당 길이 (Cowork 1189·1191·1200)

- **1초 단위로 직접 적는 숫자 칸**이다(목록이 아니다 — 캡틴D 2026-10-05). 범위는 1초 ~ 공유
  `photoCardMaxDurationSeconds(사진 수)`, 곧 사진 수 × 길이가 `PHOTO_CARD_MAX_TOTAL_DURATION_SECONDS`(릴스 한도)를
  넘지 않는 가장 긴 값. 세 화면(명언 카드·뉴스 릴 만들기, 설정)이 모두 `components/ui/PhotoCardSecondsSelect.tsx` 를 쓴다.
- 범위 밖·정수 아님은 올려 보내지 않고 칸 아래 rose 안내(`-invalid`)로 말하며, 칸을 벗어날 때 가장 가까운 허용값으로
  맞춘다. 칸 아래 안내 줄은 「사진 N장이면 한 장당 최대 M초」를 말한다.
- 만들기 화면에서 사진을 더 골라 지금 값이 한도를 넘으면 **허용되는 가장 긴 값**으로 바로 내린다(가장 짧은 값이 아니다).
  설정 화면은 내리지 않는다(`autoClamp={false}`) — 저장값이 한도를 넘었다는 사실을 보여 주고 저장을 막는다.
- 합계는 늘 한 줄로 보인다: 만들기 화면 「사진 N장 × 한 장당 X초 = T초 / 최대 180초」, 설정 화면 「사진 N장 ×
  X초 = 총 T초 / 180초」. 넘으면 그 줄을 rose 로 바꾸고 이유를 붙이며 저장·다음 버튼을 막는다.
- 설정 화면에서 사진 카드는 모델 요금·모델 범위 줄을 보이지 않는다(사진은 생성비가 없다). 일반 영상 프로젝트의
  모델별 목록·요금 안내는 그대로다.
- 응답 가드는 **형식만** 본다(`CLIP_DURATION` 범위 또는 1~180 정수). 사진 수 대비 한도는 화면과
  서버가 판단한다 — 가드에서 거르면 한도를 넘은 카드가 화면에서 사라져 안내조차 못 한다.

### 3.11 밈 트렌드 — 근거가 있는 숫자만 (CLI 1268·1269, 2026-10-08)

- 자리: 왼쪽 「만들기」 묶음의 끝(`memeTrends`, 오르는 선 아이콘). 고른 후보는 주소 `?trendId=` 에 싣는다.
- **범위 줄은 항상 보인다**: 출처(YouTube 공식 API · 한국 · 4분 미만), 마지막 수집 시각, 「Instagram·TikTok 유행은
  포함하지 않고 영상 속 말·동작은 분석하지 않았다」, 묶는 하한(공유 `MEME_TREND_MIN_CHANNELS`·`MIN_VIDEOS`).
  이 줄이 없으면 화면이 「지금의 유행 전부」로 읽힌다.
- **숫자는 셋**: 공개된 최고 조회수, 묶인 영상 수, 서로 다른 채널 수. 트렌드 점수·합산 조회수를 만들지 않는다.
  비공개 조회수는 「비공개」로 쓰고 0 으로 채우지 않는다. 조회수 옆에는 **읽은 시각**을 붙인다.
- 증가분은 재수집으로 `previousViewCount` 가 있을 때만 「지난 수집 이후 +N회」. 한 번 읽은 숫자로 확산을 말하지 않는다.
- 「같은 밈」의 근거는 실제로 본 해시태그·문구 칩뿐이다. 해시태그는 `#` 째로, 문구는 따옴표 안에 본 그대로.
- 화면을 여는 것은 저장된 목록 읽기(할당량 0)이고, 할당량을 쓰는 건 「YouTube에서 다시 모으기」(outline) 하나다.
  실패해도 보고 있던 목록은 지우지 않는다. 키 없음만 「API 설정 열기」를 함께 띄운다(할당량 끝은 설정으로 풀리지 않아 버튼이 없다). 할당량은 구글 기준
  태평양 시간 자정에 돌아오므로 「내일」이라 쓰지 않고, 남은 할당량이나 무료 한도도 말하지 않는다(프로젝트마다 다름).
- **흐름 띠(2026-10-09):** 범위 줄 아래에 `StepRibbon`(밈 고르기 → 관찰 카드 → 초안 만들기 → 영상 제작)과 한 줄 안내. 단계는 화면 상태에서 읽는다 — 고른 후보 없음 = 1, 후보를 골랐고 저장한 카드 0개 = 2, 저장한 카드 ≥1 = 3. 「영상 제작」은 이 화면 밖(만들어진 단기 프로젝트)이라 항상 upcoming. 1단계만 누를 수 있고(고른 후보 해제) 나머지는 표시일 뿐이다. 저장하지 않은 입력은 단계를 올리지 않는다. 띠는 `sticky top-0 z-10 bg-ground`로 스크롤해도 화면 위에 남고, 후보를 고르면 목록은 고른 한 장만 남기고 「다른 밈 고르기」로 되돌린다. 앱 본문 `<main>`은 `overflow-clip`(스크롤 컨테이너가 아니다)이어야 sticky가 창 스크롤에 붙는다 — `overflow-y-auto`면 main이 스크롤되지 않아 모든 `sticky`가 조용히 안 먹는다.
- **「이 밈으로 만들기」(2026-10-09 도입, 2026-10-10 CLI 1340 개정 — 제안 검토를 건너뛰지 않는다):** 후보를 고르면 목록 맨 위에 `MemeQuickMake` 카드(`border-violet-400/40 bg-violet-500/10`)가 나온다. ① 이미지 보관함의 캐릭터(폴더·낱장, 썸네일 + 이름, `role=radio` 선택 = 선택 레시피) 하나를 고르고 ② 「이 밈으로 만들기」(primary)를 누르면 **저장된 관찰 카드만**으로 장면 계획을 채워 단기 프로젝트를 만들고 고른 캐릭터를 주인공으로 연결한다. **이 카드는 Gemini를 부르지 않고 분석 제안을 카드로 저장하지도 않는다** — 예전의 「분석 → 제안 전부 카드 저장 → 프로젝트」 한 번에 가기는 사람이 제안을 비교·고르는 단계를 건너뛰어서 없앴다. 저장된 카드가 없으면 버튼이 꺼지고, 상황을 문장으로 말한 뒤(분석 제안이 있지만 아직 카드로 저장하지 않았음 / 카드가 아직 없음) 「관찰 카드 열기」(아래 접힘을 펼치고 그리로 스크롤)와 「분석 없이 만들기」(일반적인 틀)를 준다. 관찰 카드 칸에서 저장하면 그 저장 시각이 위로 올라와 이 카드가 저장본을 다시 읽는다(GET, 같은 시각이면 다시 읽지 않음). 저장본을 읽지 못하면 무엇으로 만들지 모르므로 만들지 않는다. 프로젝트는 만들어졌는데 캐릭터 연결이 실패하면 **이동하지 않고** 이 카드에서 알리고(이동하면 화면이 사라져 못 본다) 「캐릭터 다시 연결」·「캐릭터 없이 프로젝트 열기」를 준다. 폴더 이름·주제·장면 계획은 자동으로 채운다. 만들어진 뒤의 대본 승인·영상 전송 승인은 그대로다(이 화면은 OpenAI·Runway를 부르지 않는다).
- **화면 정리(2026-10-10, 「필요 없는 태그·파트는 빼서 깔끔하게」):** 같은 말을 두 번 하지 않는다. 후보 카드는 이름·최고 조회수·영상 수·채널 수·최근 게시만(이름이 첫 근거라 칩을 되풀이하지 않음), 근거 칩은 선택 뒤 상세 「묶은 근거」에서 영상 수와 함께 한 번만. 띠 옆 안내는 첫 단계에만(후보를 고른 뒤에는 「이 밈으로 만들기」 카드가 할 일을 말한다). 선택 후에는 「← 다른 밈 고르기」 버튼만 둔다. 하단 해설 문구는 범위 줄과 영상별 「읽은 시각」이 이미 말하므로 뺀다. 증가 속도는 **계산된 영상에만 영상 줄에** 붙이고, 계산되지 않은 이유(이전 값 없음·24시간 미만·맞지 않음·일부만)는 목록 위 한 줄(`meme-growth-summary`)이 한 번만 말한다. 묶인 영상은 처음 5편만 보이고 나머지는 「더 보기」. **남기는 것:** 조회수의 읽은 시각, 서로 다른 채널 수, 「영상 속 말·동작은 아직 분석하지 않았다」 한계(범위 줄), API 오류·오래된 수집 경고. 관찰 카드는 「관찰 카드 — 영상 분석·제안 비교·직접 적기」 접힘 안에 있다(「이 밈으로 만들기」의 「관찰 카드 열기」가 펼친다). 서버가 준 후보 이름·영상 출처는 지우지 않는다.
- 상태색: 오류 rose, 수집이 24시간 넘게 지남 amber(`role=status`), 기억한 후보가 목록에 없음 sky(정보).
  선택한 카드는 「현재 위치·선택」(`border-violet-400/50` · `bg-violet-500/15`, `aria-pressed`).
- 영상 링크는 새 탭(`rel="noopener noreferrer"`), 썸네일은 `referrerPolicy="no-referrer"`.

#### 밈 관찰 카드 (② — CLI 1278·1280)

- 고른 후보 상세 아래 한 카드(`MemeObservationPanel`). 열 때는 저장된 작업 공간만 읽는다 — Gemini 호출 0.
- **근거별 대표 영상(CLI 1340)** — 분석 칸 위 `dl`. 계산된 역할만 줄로 그린다: 「도달 규모」 = 공개 조회수가 가장 큰 영상(조회수와 함께),
  「실측 증가」 = `memeVideoGrowth()`가 계산된 영상 중 하루 평균 증가가 가장 큰 영상(「지난 수집 이후 하루 평균 +N회」), 「내용 분석」 = 분석이
  성공해 저장된 출처 영상들. 계산되지 않은 역할은 줄째 없다. 「공통 패턴」 같은 검증하지 않은 결론은 쓰지 않는다.
- 분석은 「이 영상 분석 (Gemini 1회)」(outline) 하나, **한 번 누르면 한 편**. 영상은 `select`(「채널 · 제목 · 조회수」), 기본은 공개 조회수가 가장 큰 영상. 자동 분석·자동
  재시도·연속 분석 없음. **한 후보에서 서로 다른 제작자의 영상 3편까지**(`MEME_ANALYSIS_SOURCE_LIMIT`): 이미 분석한 제작자의 다른 영상, 이전 출처가 피드에서
  빠져 제작자를 확인할 수 없을 때의 새 영상, 3편을 채운 뒤의 새 영상은 선택지에서 꺼지고(「지금 분석 못 함」) 고르면 amber `role=status`로 이유를 말하며 버튼이 꺼진다.
  이미 분석한 영상은 「· 분석함」이고 「이 영상 다시 분석 (Gemini 1회 · 이 영상 제안만 바뀜)」으로 열려 있다. 화면 판단이 어긋나도 서버 코드
  (`MEME_ANALYSIS_CHANNEL_ALREADY_USED`·`_SOURCE_UNKNOWN`·`_SOURCE_LIMIT`)가 막고, 그 문장은 「요청은 보내지 않았고 횟수도 그대로」로 끝난다. 옆에 「오늘 N / 3회」, 횟수를 모르면(`dailyCalls=null`) 숫자 대신 이유를 쓰고 버튼을 끈다. Gemini 키 결제
  조건(`PROVIDER_KEY_NOTES.gemini`)은 버튼 아래 amber 로 그대로.
- **제안 비교(CLI 1340):** 제안은 출처 영상마다 한 칸(`section`, 2편 이상이면 `lg:grid-cols-2 xl:grid-cols-3`)으로 나란히 — 칸 머리에 「제목」 · 채널
  (피드에서 빠졌으면 「목록에서 빠진 영상 (ID)」, 분석은 지우지 않는다), 분석 시각·모델. 제안 ID는 출처마다 겹칠 수 있어 출처 영상과 함께 구분한다.
- **제안과 카드는 다른 층이다.** 제안 = 모델이 낸 것, 읽기 전용, 「제안일 뿐」·분석한 영상·시각·모델을 함께. 카드 = 사람이
  저장한 것. 분석이 성공해도 카드는 바뀌지 않고 「카드로 가져오기」한 것만 복사된다. 실패·키 없음에도 카드 칸은 그대로라
  **직접 적는 길이 항상 열려 있다** — 오류 문장도 그 길로 끝난다.
- 카드 출처 표시: 「Gemini 제안에서 가져옴」/「직접 적음」, 가져온 뒤 원문과 달라지면 「· 고침」(서버 플래그 없이 비교). 제안에서 가져온 카드는
  옆에 출처 영상과 분석 시각을 함께 쓴다. 가져오기는 저장이 아니다 — 「카드 저장」을 눌러야 남고, 「이 밈으로 만들기」는 저장된 카드만 쓴다.
- 저장 전 화면이 먼저 말한다: 빈 글자, 200자 초과, 0–600초·소수 한 자리, 끝 < 시작. 미저장은 amber `role=status`
  (막지 않음). 동시 저장 409 는 입력을 그대로 두고 「다시 읽기 (입력 유지)」.
- 후보가 목록에서 빠지면 「같은 후보가 다시 모이면 저장한 카드가 다시 열린다」고만 말한다. 카드가 지워진다고 쓰지 않는다
  (서버가 지우지 않는다).

#### 밈에서 단기 프로젝트 초안으로 (③)

- 저장한 카드가 하나 이상일 때만 「이 카드로 애니메이션 초안 만들기」(outline)를 보여 준다. 카드에 미저장 수정이 있으면 버튼을 끄고 먼저 저장하라고 amber로 알린다.
- 한 화면에서 새 주제·캐릭터·상황·2–12장면의 로컬 계획을 수정한다. 관찰 카드는 참고 출처로만 쓰고 원본 영상·음원·대사·얼굴을 결과물에 복제하지 않도록 지시한다.
- 「이 계획으로 단기 프로젝트 만들기」가 유일한 primary다. 누르면 기존 단기 프로젝트 설정으로 이동한다. 이 단계는 Provider 호출이 없고, 대본 승인 화면에서 비용을 확인한다. 오류는 rose alert로 표시하고 입력은 유지한다.

### 3.12 이야기 만들기 — 소설을 장기 프로젝트로 (2026-10-09, 캡틴D 요청)

- **정보 구조(2026-10-10, 캡틴D 실사용 혼란 — CLI 1326·1327): 이야기 만들기는 사이드바의 독립 항목이 아니라 장기 프로젝트의 「소설에서 시작」이다.** 경로는 **「장기 프로젝트」(목록) → 「새 작품 만들기」(`longStart`, 시작 방법 고르기) → 「직접 설정으로 시작」(`longCreate`) 또는 「소설에서 시작(이야기 만들기)」(`storyStudio`)**. 두 시작 방법은 서로 오갈 수 있고(각 화면 머리의 「소설에서 시작하기」/「소설 없이 직접 설정으로 시작」), 둘 다 **같은 장기 프로젝트**를 만들어 같은 작품 작업공간(작품 한눈에 보기·작품 기본 설정·회차 나누기·회차·인물·영상)으로 합류한다. `storyStudio` 주소는 그대로 두고, 사이드바에서는 「장기 프로젝트」 아래에 켜진다(독립 항목 제거). 생성 뒤 「작품 기본 설정」은 **그 작품의 수정 화면**이라고 머리에 적는다(소설을 분석 없이 만들었다면 원문은 「개요」 칸에 있다). 새 작품을 만든 직후 도착한 화면에는 **한 번만** 안내가 뜬다 — 분석 없이 만든 경우(「이미 프로젝트가 만들어졌고 원문은 설정의 개요에 그대로 저장돼 있으며 아직 AI 분석은 하지 않았습니다. 돌아가면 이 작품의 화면」, 도착지는 회차 나누기), 분석을 확인·수정해 만든 경우(「회차 개요와 인물이 이미 채워져 있어 회차 나누기 없이 회차 작업으로」, 도착지는 작품 한눈에 보기). 그 작품을 떠나면 사라진다.
- **Enter 로는 아무것도 만들어지지 않는다**(CLI 1326): 이 화면의 form에는 submit 버튼이 없고, 「분석 없이 장기 프로젝트로 만들기」(`type=button`)와 유료 분석의 승인 버튼이 각자 직접 눌러야만 동작한다.
- **화면 칸(4단계, 위에서 아래):** ① 이야기(제목·한 줄 줄거리·본문 붙여넣기 — 분석 없이 만들기는 6,000자, AI 분석은 120,000자까지(M4)·출처 메모·권리 확인·회차 수·장면 수) ② **AI로 먼저 분석해 보기(유료·선택, 아래 M1)** ③ 등장인물(선택, **분석 없이 만들 때만**, 이름·설명 + 이미지 보관함 캐릭터와 짝짓기) ④ **분석 없이 바로 장기 프로젝트로 만들기**(M0, 유일한 primary가 아니라 이 칸의 버튼 하나 — 분석 승인 버튼이 따로 있다). 회차 수·장면 수 칸은 AI 분석의 입력이라 ①에 있고(기본 3회차·6장면), 만든 뒤에는 **장기 프로젝트 설정**에서 조절한다 — 「회차 나누기(AI)」 화면은 회차 수를 보여 줄 뿐 조절 UI가 없다(CLI 1310).
- **AI 분석(M1, 유료 1회 — `StoryAnalysisPanel`):** 칸 순서는 ① 이야기(회차 수·장면 수 칸이 AI 분석 입력이라 다시 생김) ② **AI로 먼저 분석해 보기(유료·선택)** ③ 등장인물(선택) ④ 분석 없이 바로 장기 프로젝트로 만들기. ②는 **「분석 미리보기 만들기 (무료)」 → 보낼 내용 확인(모델·본문 글자 수·고정 견적 $0.05·이번 달 예산·OpenAI로 보낼 글 전체 보기) → 별도 버튼 「승인하고 분석 보내기 (유료 약 $0.05)」** 순서이고, 승인 전에는 유료 요청이 나가지 않는다. 미리보기 뒤 입력이 한 글자라도 바뀌면 승인 버튼이 꺼지고(서버도 해시가 다르면 거절), 키가 없거나 예산이 모자라면 이유를 말하고 API 설정으로 보낸다. 자동 재시도는 없고, 오류는 코드마다 고정 문장(요청이 나갔나·청구됐나·지출 기록이 남았나가 다음 할 일을 정한다). 분석 응답(줄거리·인물·회차 구성·주의 표지·출처 메타데이터)은 이 화면이 보관했다가 아래 M2 확인·수정 화면에 넘기고, 같은 입력의 지난 결과 재사용(`reused`)·저장 안 됨(`saved`)·지출 기록 실패(`spendUnrecorded`)를 문장으로 말한다. **법적 권리나 원문과 비슷하지 않다는 보장을 하지 않는다고 결과에 적는다.**
- **확인·수정 화면과 프로젝트 확정(M2, `StoryAnalysisReview`):** AI 분석 결과는 읽기 전용 카드가 아니라 **모든 칸을 고칠 수 있는 화면**이다 — 줄거리(제목·장르·한 줄 줄거리·분위기·주제), 인물 카드(이름·외모·성격, **주인공 라디오 — 정확히 한 명**, 인물 추가·빼기, 주인공은 뺄 수 없음), 회차 카드(제목·요약·핵심 사건·갈등·마지막 장면·다음 화로, ↑↓ 순서·추가·빼기, 번호는 항상 1..n). 칸은 서버 한도(칸마다 글자 수·인물 1–40명·회차 1–20회)를 `maxLength`로 먼저 지키고 빈 칸은 「비워 둘 수 없습니다」와 위쪽 「비어 있는 칸 N개」로 알린다. 주인공의 이미지는 보관함의 **캐릭터 폴더**(켜진 폴더만)에서 선택하며 비우면 연결하지 않는다. **「이 구조로 장기 프로젝트 만들기」(primary)는 `POST /long-projects/from-story-analysis` 저장 요청 하나**이고 본문·분석·미리보기·Provider 요청은 없다(원문은 이 화면에도 서버에도 없다). 입력이 바뀌어 결과가 stale이면 확정을 끄고 새 분석을 요구한다. **출처 메모는 `settings.notes`가 아니라 `source`(서버의 `novel_story_source.json`)에만 남는다** — 서버가 `notes`를 회차 대본 프롬프트에 넣기 때문에 M2의 `notes`는 빈 문자열이다. 오류는 기존 장기 프로젝트 고정 문장만 보이고 편집한 내용은 그대로 둔다. 확정 뒤에는 회차 개요가 이미 채워져 있으므로 **「회차 나누기(AI)」가 아니라 장기 프로젝트 상세로** 이동한다(M0 「분석 없이 만들기」만 회차 나누기로).
- **인물 캐릭터 이미지(M3, 유료 1장 — `CharacterImageControl`):** 확인·수정 화면의 **인물 카드마다** 「캐릭터 이미지 (유료 약 $0.10, 선택)」 상자가 있다. 순서는 **「이미지 미리보기 (무료)」 → 보낼 내용 확인(모델·크기·고정 견적·이번 달 예산·그림 모델로 보낼 글) → 별도 버튼 「승인하고 이미지 만들기 (유료 약 $0.10)」** 이고, 화면을 열거나 미리보기를 만들거나 프로젝트를 확정하는 것만으로는 이미지 요청이 나가지 않는다. 미리보기 뒤 인물 설명이 바뀌면 승인이 꺼지고, 키·예산이 막으면 이유와 API 설정 이동을 준다. 자동 재시도는 없고 `ALREADY_ATTEMPTED`는 「다시 눌러도 보내지 않는다」고 말한다. 결과 그림은 보관함 캐릭터 폴더(`/assets/{folderAssetId}/content`)이며, **주인공 카드에서만** 사람이 그림을 본 뒤 따로 누르는 「이 그림을 주인공 이미지로 쓰기」로 연결을 고른다(만들었다고 자동 연결하지 않고, 주인공이 바뀌거나 그 인물의 이름·외모·성격이 바뀌면 그 연결은 풀린다). **결과는 만들 때의 설명과 묶여 있어서**, 설명을 바꾸면 옛 그림은 「바뀌기 전 설명으로 만든 그림」으로 흐리게 표시되고 연결 버튼이 없으며, 지금 설명으로는 미리보기→승인으로 새로 만든다(요청을 기다리는 동안 설명이 바뀌어도 그 결과는 새 설명에 붙지 않는다). **조연 카드에도 「이 그림을 이 조연의 이미지로 쓰기」가 있다(M4)** — 주인공과 같은 규칙(사람이 따로 눌러야 연결, 그 조연의 설명이 바뀌거나 주인공이 되거나 빠지면 풀림). 그림 저장에 실패해도 서버가 이미 치른 PNG를 돌려주면(`recoveryImageBase64`) 「이미 만든 그림 내려받기 (PNG)」 링크를 준다. 만든 뒤 보관함 캐릭터 폴더 목록을 다시 읽는다.
- **권리 확인 체크(필수)**: 「제가 직접 쓴 글이거나 작성자의 이용 허락을 받은 글입니다」를 체크하지 않으면 만들 수 없고(Reddit 약관·저작권 조사, CLI 1305), 확인 사실은 M0(분석 없이 바로 만들기)에서는 프로젝트 메모에, AI 분석을 거친 M2에서는 서버가 보관하는 출처 기록(`source.rightsConfirmedAt`)에 남는다. Reddit 주소로 자동 가져오기는 Reddit의 사전 승인·이용 조건 때문에 만들지 않는다고 점선 상자에 적는다.
- **되는 것만 버튼으로 그린다.** 「분석 없이 만들기」(M0)가 보내는 요청은 장기 프로젝트 생성 한 번뿐이고(재창작·영상화 지시, 출처, 권리 확인, 등장인물은 프로젝트 「메모」에 글로 들어간다) AI·이미지·영상 요청은 없다. AI 분석(M1)과 인물 이미지(M3)는 각자 위의 미리보기→별도 승인 규칙을 따른다. 이후 회차 개요·대본·그림·영상과 그 승인은 장기 프로젝트의 기존 흐름이다.
- **아직 안 되는 것(Reddit·웹소설 플랫폼에서 가져오기, 한국어 만료 작품(공유마당) 가져오기, 120,000자보다 긴 글을 한 번에)은 점선 상자의 글로만 알린다** — 눌러도 아무 일 없는 버튼은 그리지 않는다(§7). 그 상자에는 「남의 글은 작성자 허락·라이선스를 확인하라」는 한 줄도 둔다. 인물 자동 추출과 캐릭터 이미지 등록은 이제 AI 분석(M1)·인물 이미지(M3)로 **있으므로** 「준비 중」으로 적지 않는다(CLI 1325).
- **작품 고르기 — 저작권이 끝난 소설(CLI 1345, 캡틴D 1343·1344, `NovelSourcePicker`):** 「소설에서 시작」의 맨 위, 1. 이야기 위의 선택 칸. 직접 붙여넣는 길은 그대로다. **범위 문단이 항상 보인다**: Project Gutenberg 영어 원문만 · 저자·번역자가 모두 기준 연도(`novelSourceDeathYearCutoff()`, 2026년이면 1955년)까지 사망 · **보수적인 필터일 뿐 법적 보증이 아님** · 목록 단계에서는 분량을 모름(작품을 골라 「길이 확인」) · 한국어 만료 작품(공유마당)은 이용 조건 확인 전이라 없음. 검색은 제목·작가(영어) 칸 + 장르 `select`(한국어 이름 + 보내는 영어 주제어를 함께 표시)와 「검색」(outline) — 누를 때만(Enter 포함), 자동·주기 수집 없음. 결과는 2열 카드(제목, 「저자 (~사망 연도)」, 번역자, 주제어 3개, 「원본 페이지」 새 탭 `rel=noopener noreferrer`, 「길이 확인」 smallOutline), 고른 카드는 선택 레시피(`border-violet-400/50 bg-violet-500/15`), 이전/다음 쪽. 「길이 확인」은 **그 한 편만** 받아 전체 글자 수·장 수와 권리 근거를 보인다. 한도(120,000자) 안이면 「N자를 쓸 수 있습니다」(emerald) + 「이 본문 쓰기」(outline, 본문 칸에 글이 있으면 「지금 본문을 바꿉니다」). 넘으면 **이어진 장 범위**(처음 장·끝 장 `select`, 끝 장은 처음 장 이후만)와 장별 글자 수 목록(스크롤 `ol`, 범위 안은 bone·밖은 faint), 「1–3장 · 약 N자」 합계(넘으면 amber, 「이 범위 가져오기」 꺼짐), 서버가 그래도 길다고 하면(`selectionTooLong`) amber status, 장 경계를 못 찾으면 직접 붙여넣으라고 말한다. 1부·2부처럼 한 작품을 여러 작품으로 나눌 수 있다고 말한다. 「이 본문 쓰기」를 누르면 본문을 넣고, 제목·출처 메모는 **비어 있을 때만** 채우며(「제목 — 저자 (~연도) · Project Gutenberg #id · a–b장」), **권리 확인은 풀어서 다시 받는다**. 1. 이야기 안에 「가져온 작품」 상자(제목·저자·번역·장 범위·고른/전체 글자 수·권리 근거·원본 페이지, 가져온 뒤 본문을 고치면 「출처 기록은 그대로 함께 보냅니다」, 「가져온 작품 기록 지우기」)가 생기고, 권리 체크 문구가 「저작권 보호기간이 끝난 작품으로 쓰겠습니다 — 필터는 법적 보증이 아니고 판본·번역 권리까지 확인하지 않으며 확인 책임은 사용자」로 바뀐다. 분석 입력에는 원문 없는 출처 기록(`source`)이 실리고, 분석 없이 만들기(M0)의 메모 권리 줄도 만료 작품 근거로 쓴다. 본문은 화면 입력에만 있고 저장하지 않는다. 오류는 `NOVEL_SOURCE_*` 코드마다 고정 문장(rose alert). 이 칸의 요청은 유료가 아니며, 분석은 여전히 2번의 미리보기 → 별도 승인이다.
- **긴 글(M4-3, CLI 1333):** 6,000자를 넘으면 「분석 없이 만들기」 버튼이 꺼지고 「AI 분석으로만 진행할 수 있습니다」라고 말한다. 120,000자를 넘으면 둘 다 막고 「너무 깁니다」. 분석 미리보기는 **호출 수를 숨기지 않는다** — 「N회 (긴 글이라 M조각으로 나눠 … 마지막에 1회 합칩니다)」 또는 「(한 번에 분석합니다)」, 비용은 「$X (호출 N회 × 1회당 $0.05 고정 견적)」, 승인 버튼에도 「유료 약 $X · 호출 N회」. 보낼 글은 호출 순서대로 모두 펼쳐 볼 수 있다(마지막 합치기 글의 앞 결과 자리는 표시로). 미리보기의 프롬프트 수와 호출 수가 다르면 응답을 믿지 않는다.
- **조연 연결(M4-1, CLI 1332):** 확인·수정 화면의 조연 카드마다 보관함 캐릭터 폴더 선택(켜진 폴더만, 「연결하지 않음」 기본). 같은 폴더를 두 조연(또는 주인공과 조연)에 고르면 확정을 막고 이유를 말한다. 연결은 그 인물이 주인공이 되거나 빠지면 풀린다. 만든 뒤에는 **장기 프로젝트 설정의 「조연」 카드**(`SupportingCastCard`, 「주인공 이미지」 카드 바로 아래)에서 고친다 — 저장은 목록 전체를 바꾸는 PATCH 하나(빈 목록 = 모두 해제), 저장 안 한 변경·중복·실패는 각각 문장으로. 직접 설정으로 만든 작품에는 조연 카드가 없다고 말한다. 연결된 폴더는 **아직 그림이 없는 회차**의 참고 이미지에만 들어간다고 카드에 적는다.
- **회차 × 단계 보드(M4-2, CLI 1334):** 작품 한눈에 보기의 단계 누계와 회차 목록 사이. 행 = 회차(「N회 · 제목」, `th scope=row`), 열 = 개요·대본·이미지·영상·병합, 표에 sr-only caption. 칸 상태는 네 가지 — 완료(emerald)·지금 할 차례(violet)·아직(faint, **버튼 아님**)·확인 필요(점선). **중단·실패는 어느 단계에서 멈췄는지 계약에 없으므로(CLI 1337) 단계에 귀속시키지 않는다** — 행 머리에 「중단됨(amber)/실패(rose) — 멈춘 단계는 기록돼 있지 않습니다」 배지를 달고, 다섯 칸은 완료로 단정하지 않고 모두 「확인 필요」(누르면 그 단계 화면으로 이동해 직접 확인). 이어하기의 이동 화면은 재개 진입점일 뿐 실패 단계의 근거가 아니다. 칸은 그 회차의 그 단계 화면으로 **이동만** 한다(이미지 칸은 연결 검토 전이면 연결 검토로) — 생성·유료 요청은 그 화면의 승인으로만. 버튼 이름은 「N회 단계: 상태 — 화면 열기」. 좁은 화면은 표만 가로 스크롤(`overflow-x-auto`, 페이지는 스크롤하지 않음). 회차가 없으면 「회차 나누기(AI)」로 만들라고 말한다. 원시 상태 이름은 화면에 쓰지 않는다.
- 폴더 이름은 `이야기_<제목>_MMDD_HHmmss`로 자동.
- **M0(분석 없이 만들기)의 실제 동작을 화면이 말한다(CLI 1310):** 붙여넣은 글은 `settings.overview`로 프로젝트에 **그대로 저장**되고 기존 회차 나누기 AI가 읽는다. 메모에 재창작 지시를 넣지만 복사를 구조적으로 막지는 못하므로 「다시 씁니다」를 약속하는 문구는 쓰지 않는다(`story-m0-notice`). 원문 대신 AI가 정리한 구조만 쓰는 길은 AI 분석(M1) → 확인·수정(M2)이다.
- **만든 뒤 도착지:** 분석 없이 만든 작품(M0)은 **「회차 나누기(AI)」**(개요 미리보기 — 회차 개요가 아직 비어 있어서), AI 분석을 확인·수정해 만든 작품(M2)은 **작품 한눈에 보기**(회차 개요·인물이 이미 채워져 있어서). 전체 설계(AI 분석 → 확인·수정 → 장기 프로젝트 채움 → 인물 이미지)는 `docs/08_NOVEL_TO_ANIMATION.md`.

## 4. 화면 패턴

### 4.1 화면 공통 골격

```tsx
<ScreenHeader
  title={화면 제목}
  description={한 줄 설명(선택)}
  onBack={…}                       {/* 뒤로갈 곳이 있을 때만 */}
  backLabel="프로젝트 목록으로"      {/* 말만. 화살표는 부품이 그린다 */}
/>
{/* 그 아래 본문 섹션들, 섹션 간 space-y-5 */}
```
🟠 **이 마크업을 손으로 적지 않는다** — `ui/ScreenHeader.tsx` 를 쓴다(§3.8).
같은 다섯 줄을 16개 화면이 붙여넣기로 갖고 있었고, 그 중 다섯은 이미
`text-slate-200`(§2.1 에 없는 색)으로 갈라져 있었다.

화면 제목은 사이드바 항목명과 일치시킨다. 화면당 `<h1>` 은 하나이고,
`ScreenHeader` 를 쓰면 그것이 자동으로 지켜진다.

### 4.2 장면 그리드

장면 목록은 항상 `grid gap-3 sm:grid-cols-2 xl:grid-cols-3`을 사용한다 —
장면 수는 프로젝트별로 2~12개까지 달라지므로 마지막 행이 꽉 차지 않아도
된다. 장면 카드 구성(위→아래):

1. 헤더 행: `Scene N` (`text-sm font-semibold text-slate-100`) + 상태 칩
2. 썸네일: `aspect-[9/16] w-full rounded-xl border border-white/10
   bg-slate-800 object-cover` — 9:16 산출물이므로 세로 비율 유지
3. 메타 행: 비용·시각 등 `text-xs text-slate-400 tabular-nums`
4. 행동 행: 작은 인라인 버튼들 (`재생성`, `프롬프트 보기` 등)

현재 생성 중인 장면 카드만 `border-amber-400/40`으로 강조.

### 4.3 검토(Review) 화면

이미지·영상 검토 화면의 목적은 **비교와 확정**이다:
- 원본 이미지와 결과물을 한 카드 안에서 위아래 또는 좌우로 나란히.
- 확정 여부는 카드 테두리로: 확정 `border-emerald-400/30`, 미확정 기본.
- 전체 확정 현황을 상단에 요약 (`N장면 중 M장면 확정` —
  `text-sm text-slate-300 tabular-nums`).
- 병합 CTA는 전체 장면 확정 전까지 disabled + 이유를 보조 텍스트로 표시.

### 4.4 비용·승인 화면 (돈이 걸린 화면)

- 비용 요약은 화면에서 가장 큰 카드로, 기본 카드 규격 + 내부에 정의 목록:
  좌 레이블 `text-sm text-slate-400`, 우 값 `text-sm font-semibold
  text-slate-100 tabular-nums`. 총액 행만 `text-lg`.
- 예상 비용과 남은 예산을 항상 같은 카드에 함께 표시.
- 승인 CTA는 주 CTA 규격, 명시적 라벨. 근처에 장식 요소·글로우 추가 금지.
- 취소·수정은 보조 버튼으로 CTA 왼쪽에.

### 4.5 진행(워크플로우) 화면

- 전체 진행은 `WorkflowProgressBar` 재사용.
- 장면별 순차 진행은 장면 그리드 + 상태 칩으로 표현.
- 중단·재개 버튼은 보조 버튼 규격 (위험 버튼 아님 — 중단은 파괴적이지 않다).
- 실패 장면 카드에는 오류 배너 대신 카드 내 `text-xs text-rose-400` 한 줄
  + `재시도` 인라인 버튼 (재시도는 비용 재승인 흐름으로 연결).

## 5. 앱 셸

### 5.1 배경

앱 루트의 radial violet 그라데이션 + 34px 격자선(App.tsx의 인라인
backgroundImage)은 셸 전용이다. 개별 화면·카드에 배경 이미지를 추가하지

화면에서만 사용한다.

### 5.2 사이드바

현행 구조 유지: 워드마크 → 주 네비(NavBar) → 컨텍스트 네비(장편 워크스페이스
/ 단기 파이프라인). 폭 `w-64` 고정. 활성 항목 `bg-violet-500/15 text-white`,
비활성 `text-violet-300`. **`underline` 은 네비에서 제거한다** (링크가 아니라
현재 위치 표시이므로 배경색으로만 구분).

## 6. 접근성 (기존 수준 유지 + 통일)

- 모든 아이콘 버튼에 텍스트 라벨 또는 `aria-label`.
- 상태를 색으로만 전달하지 않는다 — 칩에는 항상 텍스트, 진행 점에는
  `aria-current="step"`.
- `role="alert"`(오류), `role="status"`(로딩), `role="progressbar"`(+value
  속성) 유지.
- 포커스 스타일 제거 금지. 입력은 §3.2의 ring, 버튼은
  `focus-visible:ring-2 focus-visible:ring-violet-500/30
  focus-visible:outline-none`.
- 본문 대비: slate-950~900 배경 위 `text-slate-400` 이하 단계는 보조
  텍스트에만. 본문 이상은 slate-300 이상.

## 7. 하지 말 것

- 새로운 색상 팔레트 추가 (slate/violet/fuchsia/pink/emerald/amber/rose
  외의 색 — teal, lime 등 금지).
- `sky` 를 §2.1 「정보·알아 두실 것」 **외의 용도로** 쓰는 것. 그 칸 하나가
  `sky` 의 전부이고, 장식·강조·구분에는 여전히 못 쓴다.
- `gold` 를 §3.9 (가) 의 「끝났다」 버튼 하나 **밖에서** 쓰는 것. 특히
  **상태 표시에 금지**다 — 그건 팔레트가 아니라 §2.1 상태색 표의 일이다.
  한 화면에 금색이 둘이면 §3.9 (가) 위반이다.
- 화면마다 다른 반경·그림자·간격 즉흥 조합 (§2.4, §2.5의 고정값만).
- 한 화면에 그라데이션 CTA 2개 이상.
- 라이트 모드 대응 코드 (다크 전용 앱이다).
- 외부 UI 라이브러리 도입 (shadcn, MUI 등 — 사용자 승인 없이 금지).
- 이모지를 UI 텍스트에 사용.
- 결제·승인 화면에 장식적 발광 요소 추가.

### 8.1 표기 빚은 얹어서 갚는다 (캡틴D 승인 2026-09-14)

위 마지막 줄이 실제로 어떻게 적용되는지, amber 를 예로 못박는다. **다음
사람이 「왜 아직 안 통일했나」를 묻지 않아도 되도록 적어 둔다.**

실측(2026-09-14, `apps/frontend/src` 전수):

```
text-amber-300      119곳      ← §2.1 의 값
text-amber-200       43곳
bg-amber-500/10       5곳      ← §2.1 의 값
bg-amber-500/[0.06]  18곳
border-amber-400/40  42곳      ← §2.1 의 값
border-amber-400/30  26곳
```

- 🔴 **금지: 표기 통일만을 목적으로 하는 일괄 커밋.** 그 커밋 하나가 프론트
  전체를 건드려서, 나중에 누구도 **「이 줄이 왜 바뀌었나」를 못 읽게** 된다.
  이건 눈에 보이는 버그가 아니라 **표기 빚**이라 급할 이유도 없다.
- ✅ **허용: 어떤 화면을 다른 이유로 이미 만지고 있을 때**, 그 화면 안의
  amber 를 §2.1 표기로 같이 맞추는 것. **기준 사례** — `c7e179f` 에서
  `PhotoCardSubtitleFieldset` 의 경고 두 줄을 맞췄다. 새 경고 하나만 고치면
  **한 화면에 amber 가 두 종류**가 되므로 같은 필드셋 안의 기존 줄까지 함께
  맞춘 것이고, 거기서 멈췄다.
- **범위는 그 커밋이 만지는 화면 안까지.** 옆 파일로 넘어가지 않는다 —
  넘어가기 시작하면 결국 위에서 금지한 일괄 커밋이 된다.
- 🟠 **그래서 위 숫자는 당분간 줄지 않는다. 그게 의도다** — 숫자가 안 줄어드는
  것을 밀린 일로 읽지 않는다.
- 같은 방침을 `sky`(§2.1) 를 비롯한 다른 표기 빚에도 그대로 적용한다.
