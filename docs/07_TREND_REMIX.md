# 트렌드 리믹스 — 기능 골격 (2026-10-08)

## 목표

캡틴D가 유행 영상의 **시선을 붙잡는 방식과 전개 리듬**을 골라, 자기 캐릭터·주제·그림체로 새로운 애니메이션 릴을 만든다. 결과는 기존 단기 프로젝트의 대본 → 이미지 → 영상 승인 → 병합 흐름으로 이어진다. 이 문서는 기능의 큰 틀이며, 화면·API·Provider 구현 완료 기록은 아니다.

## 사용자 흐름

1. **레퍼런스 고르기:** 공개 영상 링크를 기록하거나, 분석 가능한 영상을 직접 선택한다. 링크만 있을 때 앱이 파일에 접근하지 못하면 「영상 분석됨」이라고 표시하지 않고 사용자가 장면 구조를 직접 적을 수 있게 한다.
2. **패턴 보기:** 시작 1–3초의 훅, 컷의 길이와 순서, 카메라 거리·움직임, 전환, 감정의 상승과 반전을 짧은 타임라인 카드로 보여 준다. 앱이 분석한 값과 사용자가 직접 적은 값을 구분한다.
3. **내 이야기로 바꾸기:** 캐릭터·주제·분위기를 입력하면 각 카드마다 원본에서 참고할 **연출 원리**와 새 릴에서 쓸 **새 행동·배경·문장**을 나란히 놓는다. 사용자가 카드 순서와 문장을 고친 뒤 확정한다.
4. **단기 프로젝트 초안으로 보내기:** 확정한 카드를 기존 장면 수(2–12)와 길이·화면 비율에 맞춘 장면 계획으로 변환한다. 원래의 유료 대본·이미지·영상 생성 버튼과 비용 확인·명시적 승인 단계는 그대로 거친다. 전송 버튼은 초안 작성만 하며 Provider 요청을 보내지 않는다.
5. **릴 확인:** 최종 릴 옆에서 선택한 훅·전환·마무리가 구현됐는지 점검한다. 원본과의 동일함을 점수로 약속하지 않는다.

## 한 영상의 예

| 시간 | 레퍼런스에서 읽는 패턴 | 새 애니메이션 릴의 예 |
|---|---|---|
| 0–2초 | 가까운 화면과 갑작스러운 움직임으로 시선 고정 | 캐릭터 앞의 거대한 그림자가 순식간에 지나간다 |
| 2–6초 | 짧은 컷 셋으로 긴장 상승 | 도시의 불빛 세 곳이 차례로 꺼진다 |
| 6–10초 | 조용한 정지 뒤 반전 | 어둠 속 작은 꽃이 빛을 내며 화면이 열린다 |
| 마지막 | 첫 장면과 연결되는 한 문장 | 사용자가 쓴 새 문장이 이미 보이는 화면에 남는다 |

위 시간과 장면은 **설명용 예시**다. 실제 후보마다 분석한 길이와 사용자가 고른 장면 수에 맞춘다.

## 첫 구현 단위와 연결 지점

**첫 구현 단위:** 사용자가 고른 레퍼런스 1개에서 편집 가능한 패턴 카드와 새 장면 계획을 만든다. 영상 파일이 있을 때만 컷 타이밍 같은 관측값을 자동 제안하고, 링크만 있으면 수동 카드로 시작한다. 자동 검색과 출처별 다운로드는 이 단위에 넣지 않는다. 초안은 사용자가 확인하기 전 기존 프로젝트를 만들거나 바꾸지 않는다.

- 현재 `CreateProjectRequest`는 `projectId`와 `topic`만 받는다(`packages/shared/src/api.ts`). 장면 계획을 기존 `StoryPromptScreen`으로 넘기려면, 구현 시점에 **초안 저장과 대본 프롬프트의 연결 계약**을 먼저 정해야 한다. 지금은 임의 필드나 Endpoint를 추가하지 않는다.
- 새 장면 계획은 기존 단기 제작 흐름의 입구에만 놓는다. 이미지 검토, 영상 프롬프트·비용 확인, Runway 명시적 승인, 영상 검토·병합은 기존 절차를 사용한다. 뉴스 릴과 명언 카드는 별도 제품 흐름으로 유지한다(`docs/06_DECISIONS.md` D-052).
- 원본 영상·음원·대사·로고·워터마크·인물 얼굴은 결과물에 자동으로 넣지 않는다. 배경음악은 기존의 사용자 업로드·라이선스 기록 경로만 사용한다(D-001~003).

## ‘유행 찾기’ 확장 조건

나중에는 **트렌드 보드**에 후보 영상의 제목·링크·게시 시점·플랫폼·짧은 훅 설명을 모아 고르게 할 수 있다. 목록을 실제로 자동 채우려면 출처별 공식 API 범위와 사용 권한을 먼저 검증한다. 예를 들어 [YouTube Data API의 `mostPopular`](https://developers.google.com/youtube/v3/docs/videos/list)는 지역·카테고리별 인기 목록을 제공하지만, [공식 변경 기록](https://developers.google.com/youtube/v3/revision_history)은 2025년 7월부터 그 목록이 음악·영화·게임 차트 중심이라고 설명한다. [TikTok Research API](https://developers.tiktok.com/docs/en/research-api-get-started)는 승인된 연구 프로젝트용 접근을 요구한다. 그러므로 이 둘을 곧바로 ‘인스타그램 릴스 유행 전체’라고 표시할 수 없다.

후보 목록에는 조회 시각과 출처를 표시하고, 분석 가능한 영상 파일이 없는 후보는 **메타데이터 후보**로만 표시한다. 출처가 확인되지 않은 인기 점수나 실제로 보지 못한 영상의 컷 분석을 만들지 않는다.

## 첫 구현 완료 조건

- 레퍼런스 1개를 입력하고, 앱이 확인한 영상 정보와 사용자가 적은 내용을 구분해 보여 준다.
- 훅·전개·반전·마무리 카드를 수정하고, 새 캐릭터와 주제에 맞는 장면 계획을 검토할 수 있다.
- 장면 계획을 기존 단기 프로젝트의 **초안**으로 연결하며, 미리보기·이동만으로 유료 요청이 나가지 않는다.
- 링크가 열리지 않거나 분석이 실패해도 사용자의 카드 수정 내용은 보존하고 수동 작성으로 이어진다.
- 새 기능의 화면·계약·백엔드와 모의 Provider 검증이 함께 끝나기 전에는 제품 기능 완료로 표시하지 않는다.
