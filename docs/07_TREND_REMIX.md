# 밈·챌린지 트렌드 리믹스 — 기능 설계 (2026-10-08)

## 목표와 범위

캡틴D가 말한 ‘유행’은 조회수가 높은 영상 한 편의 편집 방식이 아니라 여러 사람이 따라 하는 **유행어·포즈·춤·챌린지**다. 「L을 가져가」와 「니코니코니」는 종류를 설명하는 예시이며, 현재 인기 순위에 있다는 주장은 아니다. 앱은 조회수와 확산 근거가 있는 밈을 자동으로 보여 주고, 고른 밈을 자기 캐릭터의 애니메이션 릴로 바꾸게 한다.

## 사용자 흐름

1. **인기 밈 둘러보기:** 링크를 직접 입력하지 않고 앱에서 「YouTube에서 다시 모으기」를 누르면 밈 후보 카드가 나온다. 화면 진입과 목록 읽기는 외부 API를 호출하지 않는다. 첫 단계 카드는 관찰한 해시태그·문구, 대표 영상, 조회수, 출처와 수집 시각을 표시한다. 영상 속 말·동작은 분석 단계에서만 표시한다.
2. **인기 근거 확인:** 조회수 규모와 최근 확산, 서로 다른 제작자의 참여를 구분해 보여 준다. 측정하지 못한 숫자는 추정해서 채우지 않는다.
3. **밈 고르기:** 카드를 누르면 대표 영상과 알아볼 수 있는 말·동작·타이밍을 확인한다. 실제 영상을 분석한 경우에만 그 설명을 붙인다.
4. **내 캐릭터로 바꾸기:** 캐릭터·상황을 고르면 새 배경·행동·문장으로 풀어낸 2–12장면 계획을 만든다. 사용자가 수정·확정한 뒤 기존 단기 프로젝트의 대본 → 이미지 → 영상 승인 → 병합으로 이어진다. 초안 이동만으로 유료 Provider 요청은 나가지 않는다.

## 탐색 근거

- 첫 자동 수집 경로는 [YouTube Data API 검색](https://developers.google.com/youtube/v3/docs/search/list)과 [영상 상세 API](https://developers.google.com/youtube/v3/docs/videos/list)다. 한국 지역의 최근 짧은 영상 후보에서 반복되는 이름·문구·해시태그를 **밈 후보**로 묶고, 각 대표 영상의 게시일·조회수를 확인한다. `videoDuration=short`는 4분 미만 필터이므로 이 값만으로 Shorts라고 부르지 않는다.
- 이 자동 수집은 API 설정 화면에서 한 번 `YOUTUBE_DATA_API_KEY`를 저장해야 쓸 수 있다. 검색은 최근 30일 조회수 순과 최근 7일 게시일 순의 제한된 표본이며 제목·해시태그가 겹친다는 것만 확인한다. 같은 이름이 영상 3편 이상·서로 다른 채널 3곳 이상에서 관찰될 때만 후보로 표시한다. 실제로 같은 동작을 하는지는 선택 후 영상 분석과 사용자의 확인을 거친다. 키가 없거나 API가 실패해도 링크를 직접 입력하라는 기본 흐름으로 돌리지 않는다.
- 초기 순위는 서로 다른 채널의 최상위 영상 3편 중 세 번째 조회수를 먼저 보고, 그다음 표본 영상의 합계와 참여 채널 수를 본다. 한 제작자의 여러 인기 영상이 후보 상단을 독식하지 않게 한다. 게시일·조회수는 각각 근거로 표시한다. 같은 후보를 날짜를 두고 재수집한 후에만 조회수 증가 속도를 계산한다. ‘조회수 규모’와 ‘지금 확산 중인가’를 별도로 표시한다. 서로 다른 출처의 조회수를 무리하게 합산하지 않는다.
- [YouTube 개발자 정책](https://developers.google.com/youtube/terms/developer-policies)에 맞춰 수집한 비승인 API 메타데이터는 30일 안에 다시 확인하거나 삭제한다. 오래된 캐시를 최신 조회수처럼 내보내지 않는다.
- [Gemini API는 공개 YouTube URL을 영상 입력으로 받는다](https://ai.google.dev/gemini-api/docs/video-understanding). 밈을 고른 뒤 대표 영상 소수에만 영상 이해 요청을 보내 말·동작·타이밍을 제안한다. 현재 이 기능은 미리보기이며 무료 한도와 모델 접근성이 바뀔 수 있다. 기존 Gemini 키가 있어도 실제 이용 가능 여부는 요청 결과로 판단한다. 무료 한도 실패를 유료 요청으로 자동 전환하지 않는다.
- [TikTok Creative Center](https://ads.tiktok.com/resources/help/article/how-to-use-trends?redirected=2)는 해시태그와 관련 영상의 유행을 보여 준다. 현재 확인한 공식 문서는 앱에 이 목록을 공급하는 일반 API 계약을 제공하지 않으므로, 첫 버전의 자동 수집 범위는 YouTube로 표시한다. [Google Trends API는 제한된 알파 접근](https://developers.google.com/search/apis/trends)이다. 다른 플랫폼의 링크 직접 입력은 사용자가 원할 때의 보조 경로로만 둔다.

## 영상 선정 개선 설계 (2026-10-09)

### 판단의 순서와 근거 수준

1. **발견:** 같은 검색어를 최근 30일의 조회수 순과 최근 7일의 게시일 순으로 각각 수집해 중복 영상 ID를 합친다. 조회수 순은 규모를, 게시일 순은 아직 조회수가 적은 새 참여 영상을 찾는다. 이는 YouTube 검색 결과의 제한된 표본이며 전체 유행 순위가 아니다. 명시적 새로 모으기에서만 검색 API를 사용한다. 검색 호출은 3회에서 6회로 늘어나므로 할당량과 실패를 화면에 분명히 알린다.
2. **후보:** 반복된 이름·문구·해시태그를 가진 짧은 영상이 3편 이상이고 독립 채널 3곳 이상일 때만 후보로 제시한다. 동일한 메타데이터가 실제 같은 말·동작을 증명하지는 않는다. 검색어와 제목을 그대로 따라 쓴 무관한 영상은 분석과 사람의 확인에서 걸러야 한다.
3. **확산:** 조회수는 관찰 시각과 함께 표시한다. 같은 영상의 두 관찰치가 있을 때만 `(현재 조회수 - 이전 조회수) / 경과 시간`을 계산하며, 조회수가 감소하거나 관찰 간격이 24시간 미만이면 속도를 판정하지 않는다. 게시 후 경과와 채널 평소 조회수에 비춘 보정은 현재 데이터가 없어 점수화하지 않는다. 첫 수집에는 확산 속도 대신 `아직 재측정 전`이라고 표시한다. 조회수 규모와 증가 속도는 섞어 가짜 단일 점수로 만들지 않는다.
4. **대표 영상:** 도달 규모가 큰 영상, 다른 제작자의 증가가 빠른 영상, 패턴이 가장 또렷한 영상을 별도 역할로 고른다. 두 번째 역할은 유효한 재측정이 있을 때만, 세 번째는 실제 영상을 본 사람 또는 명시적으로 실행한 영상 분석 결과가 있을 때만 결정한다. 자동으로 세 역할을 채우거나 세 영상이 같은 밈이라고 확정하지 않는다.
5. **내용 확인:** 서로 다른 제작자의 영상 3편에서 공통인 말·동작·타이밍을 대조한다. Gemini 분석은 선택한 영상 한 편씩 명시적 요청으로만 호출하며 기존 하루 3회 한도를 지킨다. 제안은 출처 영상과 시각을 붙여 보여 주고, 사람이 공통 패턴을 확인·수정한 카드만 초안의 근거로 쓴다. 실패나 한도 소진 시 직접 관찰한 카드를 입력할 수 있다.
6. **결과 검증:** 원본 클립·음원·얼굴·로고를 복제하지 않고 새 캐릭터의 파일럿 릴을 만든다. 게시 후 실제 시청 유지율·초반 이탈·완주 같은 자기 계정 지표로 다음 선정 기준을 조정한다. 앱이 그 지표를 아직 수집하지 않으므로 성과 예측이나 보장 문구는 쓰지 않는다.

### 구현 경계와 완료 조건

- **이번 단위:** 발견 표본을 두 정렬·두 기간으로 넓히고 3개 독립 채널 기준을 적용한다. 중복 ID는 영상 상세 조회 한 번만 사용한다. 기존 저장된 후보·관찰 카드·명시적 Gemini 요청 흐름은 보존한다. 모의 YouTube 응답으로 검색 파라미터, 중복 제거, 독립 제작자 기준, 실패 시 이전 피드 보존을 확인한다.
- **후속 단위:** 재측정 속도의 표시와 출처별 대표 영상 안내, 다중 영상의 분석 제안 보존·비교 화면을 shared 계약부터 차례로 연결한다. 분석 호출 수가 늘어도 자동 호출은 하지 않는다. 화면과 백엔드 검증을 모두 마쳐야 해당 단위를 완료로 적는다.
- [YouTube의 트렌드 판단 설명](https://support.google.com/youtube/answer/7239739?hl=en)은 조회수 외에 성장 속도, 출처, 게시 시각, 채널의 평소 실적, 다양성을 함께 본다. 여기서 3개 채널·7일·24시간은 이 제품을 위한 보수적 운영 기준이며 YouTube나 전문가 단체의 공식 임계값은 아니다.

## 기존 제작 흐름과 계약

`CreateProjectRequest.initialStoryDraft`는 장면 수·캐릭터·편집한 장면 계획·관찰 카드 참고 지시를 새 단기 프로젝트의 기존 설정에 함께 저장한다(`packages/shared/src/api.ts`). 계획은 로컬에서 만들고 수정하며 이 단계에서 Provider 호출은 없다. 대본 미리보기는 저장된 `fullStory`·`additionalNotes`를 읽고, 유료 대본 생성은 기존 명시적 승인 절차에서만 시작한다. 이미지 검토, 비용 확인, Runway 명시적 승인, 병합도 기존 단기 프로젝트 절차를 유지한다. 뉴스 릴과 명언 카드는 별도 흐름이다(`docs/06_DECISIONS.md` D-052).

원본 영상·음원·대사·로고·워터마크·인물 얼굴은 결과물에 자동 삽입하지 않는다. 배경음악은 기존 사용자 업로드·라이선스 기록 경로를 따른다(D-001~003).

## 첫 구현 완료 조건

- 링크를 입력하지 않고도 앱 안에서 **밈 단위**의 후보와 대표 영상별 조회수 근거를 본다.
- 후보를 누르면 여러 영상이 같은 밈인지 확인할 수 있고 출처·수집 시각을 본다.
- 실제 분석한 말·동작·타이밍을 수정해 새 캐릭터의 장면 계획으로 바꾸고, 기존 단기 프로젝트 초안으로 전달한다.
- 외부 API 또는 Gemini가 실패해도 이미 확인한 후보와 사용자의 수정 내용이 남는다. 확인하지 못한 분석·인기 수치는 표시하지 않는다.
- 화면·공통 계약·백엔드와 모의 Provider 검증이 함께 끝나기 전에는 제품 기능 완료로 표시하지 않는다.

## 구현 순서

1. 최근 YouTube 표본에서 반복 이름·해시태그의 후보와 조회수 근거를 읽는 화면. 목록 읽기는 저장 자료만 사용하며 명시적인 새로 모으기에서만 API 할당량을 쓴다. 이미 수집한 결과는 실패 시 수집 시각을 달아 보존한다. 이 단계만 완료되어도 **영상 내용 분석 전의 후보 목록**이라고 명시한다.
2. 고른 후보의 대표 영상 소수를 분석해 관찰한 말·동작·타이밍을 편집 가능하게 만든다. 실패한 분석을 추측으로 대체하지 않는다.
   구현 계약: 후보 안의 영상 한 편을 고르고 명시적인 버튼으로 Gemini를 한 번 호출한다. 영상 분석은 별도 하루 3회 장부로 제한하고 전송 뒤 실패도 1회로 센다. 결과는 마지막 성공한 **제안**으로 두며, 사람의 카드는 별도로 저장하고 직접 입력할 수 있다. 분석 실패·키 없음은 저장된 카드를 지우지 않는다. 현재 후보에서 빠진 카드도 파일에는 남긴다.
3. 저장한 관찰 카드에서 새 캐릭터·상황의 2–12장면 로컬 계획을 만들고 사람이 수정한다. 새 프로젝트와 계획을 함께 저장한 뒤 기존 단기 설정·대본 승인·비용 게이트로 보낸다. 저장하지 않은 카드로는 시작하지 않는다.
